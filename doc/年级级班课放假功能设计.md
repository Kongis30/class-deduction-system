# 按 Grade 设置班课假期

> **已废弃：** 本文描述的是旧版“假期延长班课结束日、保持课次总量”的设计。现行规则为班课假期只取消假期内课次，不延长结束日、不补课、不重算假期外老师轮换。最新方案见 [`docs/class-holiday-adjustment-implementation-plan.md`](../docs/class-holiday-adjustment-implementation-plan.md)。

## 业务范围

- 假期按同一班课 Course 下的 Grade 独立设置，实际存储范围是 `Course + Grade`。
- 同一 Grade 下不同校区、不同实际 Class 共用相同的假期日期；不同 Grade、不同 Course 互不影响；1-on-1 不受影响。
- 日期区间首尾均包含。同一个 Course + Grade 内的假期区间不能重叠。
- 放假期间不生成该 Grade 的班课课次，手动调课也不能把课程移入假期；假期结束后按原周计划继续排课，并保持课次总量。
- 已开始或已有消课记录的课次不可被假期设置取消，冲突时整笔操作失败并提示先处理课次。
- 假期不改变收据金额。SESSION 报名周期按实际上课日计算；已报名记录会在假期变动时重新计算有效期。若实际 Grade Class 的结束时间容纳不了所购课次，则拒绝保存。
- MONTH/WEEK 课包仍按报名时的固定日历周期计算。

## 数据与状态

- `course_holiday` 按 `course_product_id + grade_band` 保存假期名称、起止日和审计字段。
- 旧的 Course 级假期迁移时复制到该 Course 下每个现有 Grade，保持原来所有 Grade 都停课的业务效果；被假期取消的 occurrence 改为引用对应 Grade 的假期记录。
- `lesson_occurrence` 保留被假期影响的课次，保存关联假期及取消前的排课状态。删除或缩短假期时，仅恢复对应 Grade 中尚未开始且没有冲突的课次；人工取消的课次不会被恢复。
- `class_group.schedule_base_end_date` 保存管理员配置的原始周期结束日；有效结束日可因假期延长，后续增删假期始终从原始周期重算。缩短周期时，删除超出新周期且尚未开始、无消课记录的自动周课次。
- 假期增改删、该 Grade 下课次同步和 SESSION 报名有效期重算在同一事务中完成。
- Grade 改名时同步更新假期的 `grade_band`，避免假期与实际班级脱节。

## 上下游约束

- 所有班课课次生成入口、每日续排任务、实际班级周课表编辑及 SESSION 计费，都按 Course + Grade 查询假期。
- Prices 页面按每个 Grade 单独提供假期管理入口，并在保存前展示该 Grade 受影响的课次数、SESSION 报名数和阻止保存的冲突。
- Schedule、班课消课和学生日历继续使用 `lesson_occurrence`；假期取消的课次不会作为可排课或可消课次返回。
- 不改变已确认消课历史、付款、折扣及收据金额。
