# 1-on-1 分段排课：Create Schedule / Edit Schedule 交互设计

状态：待实现。本文补充[团课分段排课功能设计](./团课分段排课功能设计.md)没有覆盖的 1-on-1 课包流程。日期和时间沿用系统的 America/New_York 校区时区。

## 1. 现状与边界

1-on-1 页以**学生的逻辑课包**为入口：无有效排课规则时显示 Create Schedule，有有效规则时显示 Edit Schedule。现有弹窗只有一个 `startDate` 和一组不带生效日期的每周 `slots`；每个 slot 有老师、教室、课次名称及用户指定的 `allocatedUnits`。后端 `RecurringScheduleRuleServiceImpl` 已有“修改后结束旧规则、建立新版本”的机制，但这是**编辑历史版本**，不是用户预先安排的多个未来时段。

本功能在**同一个课包的一次排课计划**中配置多个未来日期段。段只定义哪些日期按哪个周课表上课；不会创建第二个课包、订单、收据或独立的消课入口。保留现有 Edit Schedule、单节 Adjust、暂停课程、老师交接及历史消课规则。每段日期含首尾，允许空档，不能交叠。

首版的多个计划段使用**同一组老师与课次名称**。管理员若需将课包交给另一位老师，仍在交接生效时使用现有 Edit Schedule 的“修改老师”操作，完成整个逻辑课包的权限迁移。首版不提供“预先指定未来某段换老师”：现有 1-on-1 消课入口按老师管理整个课包，提前设置不同段老师会使历史时间线、待处理课次的操作权和分配额归属产生歧义。团课每节课可按段换老师，不能将该规则直接复制到 1-on-1。

## 2. Create Schedule：首次排课

选中学生和 ACTIVE 课包，点击 **Create Schedule**。弹窗顶部固定显示学生、课包总课时、已消课、其他排课预留及当前可安排余额。下方显示第一张“排课段”卡片：必填开始日、结束日；在现有周历上拖选每周时段；为时段填写老师、教室/Online、课次名称和本段计划分配课时。第一段的开始日可沿用用户已选日期，结束日由用户明确选择，不默认无限延续。

用户点 **Add period** 新增空段，或 **Copy period** 复制周时段与资源后修改日期；复制不自动续接，也不复制已经分配的课时。日期必须按时间顺序排列，可有空档。每段卡片常驻摘要展示日期、每周时段、可生成节数、拟分配课时；展开后编辑。移动端一次只展开一段，其余保留摘要。

用户每改一段即可请求 **Preview lessons**，展示各段实际课次日期、时间、老师、节数和课时，另列出空档、同日冲突、超出余额的课时。**Create Schedule** 只在预览通过时可点；保存时后端重新计算并原子写入。成功后返回同一个课包详情和同一条时间线。

### 分配额与日期

- 仍由用户指定分配课时，单位沿用现有 0.5 小时。新增的各段合计不可超过课包可安排余额，且每段不能超过其日期内可生成的课时容量；不因复制段而复制预算。
- 预览同时显示“日期范围内可上课的课时”和“实际按分配额生成的课时”。若末次课时小于完整时段，延续现有尾课处理方式并明确标出；若日期范围长于分配额，后续日期不生成课次，在预览中说明。
- 若用户输入的分配额在该段日期内排不完，阻止保存并指出该段及还差多少课时。不能自动把未排完课时挪到下一段，或暗中增加分配额。
- 同一周有多个 slot 时，分配额仍落在具体 slot 上；段卡片展示汇总，不把多个 slot 的分配额混成一个不可追溯的数字。用户可以按现有方式分别设置每条周时段的计划总额。

## 3. Edit Schedule：已有课表的变更

点击 **Edit Schedule** 后完整回显当前计划段及每条周时段的老师、教室、名称和分配额。旧版只有平铺周课表的规则按原规则起始日至原结束日（若持续中则显示“持续中”）包装为单段；**仅打开或不改变内容保存，不能改动现有课次**。

弹窗中将已经开始或有处理记录的课次列在“保留的历史与例外”区域。已过去的段只读；跨越生效日的段在界面中明确切成已保留部分和可编辑的未来部分。管理员可编辑未来部分的日期、周几、时间、资源和分配额，可新增、复制或删除未来段。日期缩短、删除段或减少分配额时，必须展示受影响的普通未来课次；已完成、待审核、人工单节 Adjust 等不可直接抹掉。

点 **Preview changes** 显示四组清单：① 保留的历史/单节例外；② 将撤销的普通未来课次；③ 将生成的新课次；④ 每个 slot/老师的原分配额、调整后分配额、已消课、未处理预留和课包剩余。新旧计划日期之间的空档也应显示。若资源/学生冲突、权益不足、保留课次和新模板重复，给出可读的具体日期、时间、老师和课程名称；不展示内部 ID。仅预览通过才允许 **Save Changes**。服务端仍需在事务内重新校验，不能依赖页面预览。

| 编辑操作 | 保存后的行为 |
| --- | --- |
| 仅改未来教室、课次名称 | 保留已有历史和分配额，调整未来普通课次；不意外建立第二个课包或重算已消课。 |
| 改未来周几/时间、增删日期段 | 沿用现有规则版本链：旧版本封存，未来普通课次按新段重建；保留已处理和人工调整课次的事实与原位。 |
| 改用户指定分配额 | 仍按课包余额和已预留课时校验；不得自动覆盖其他老师、其他 slot 的分配额。减少分配额前要确认保留课次仍有足够额度。 |
| 改老师 | 按现有“整个逻辑课包交接”处理：新老师看到完整 lesson records 时间线，已处理记录保留原任课和扣课归属，未处理课次及操作权交给新老师；原老师不再保留该课包操作入口。 |
| 改开始日、缩短结束日或删除未来段 | 不改写已发生课次。预览列出失去的未来课次；若已承诺课时无法安排或与保留课次冲突，拒绝保存并说明。 |
| 点 Cancel 或重复点 Save | Cancel 不写入；Save 防重复提交，旧页面版本提交时提示刷新。 |

**单节 Adjust 与整套 Edit 的关系：** Adjust 只改指定课次，不改周模板；后续 Edit 必须保留该单节例外，并知道其原模板课位，避免生成重复课次。已处理历史一直在相同课包的 lesson records 时间线中，不能因段删除、规则版本切换或老师交接而消失。

## 4. 与上下游的关系

| 业务 | 约束 |
| --- | --- |
| 课包余额、消课与分配额 | 段是日期模板，不是课包。分配额合计、已消课、待处理课次预留及其他规则预留从同一课包账本核算；已消课金额和历史老师不重写。 |
| 1-on-1 消课页面 | 同一学生课包只有一个入口和一条完整时间线。按具体课次的实际老师与状态决定可执行操作；交接后入口归新老师。 |
| 学生日历、老师日历、教室占用 | 从生成的具体课次读取日期、时间和资源，段间空档不显示课程；保存前按实际课次检查冲突。 |
| Edit receipt 续课 | 续课增加同一逻辑课包的额度；既有分段计划不因此自动增加分配额或生成越界课次，管理员可再 Edit Schedule 扩展日期和课时。 |
| Data Summary / receipt | 分段排课不新建报名或收据。Data Summary 的课程数量、period 和权益仍按原逻辑课包与报名计算，不能按排课段拆行。 |
| 暂停、恢复、结束课程 | 保留现有状态语义。暂停不生成新课；恢复后从下一可排日期依据尚有效的段继续，已过段不补课；是否足额须在预览里提示。 |
| 课程周调整 | 现有 **Adjust Schedule** 对指定自然周生效，不改段定义；整套 Edit 之后仍须保留该周已生效的例外课次。 |

## 5. 最小落地方式与兼容

1. 保持**一个有效逻辑课包、一条当前排课规则、现有规则版本链**。给每个周 slot 增加可空的生效起止日期，在页面按同一日期范围聚合为段；历史版本仍可读取。旧版 slot 无段日期时，按当前规则的起止日期解释为单段。无需为每段新建规则或课包。
2. Create / Edit 接口支持 `segments: [{startDate, endDate, slots: [...] }]`。一次请求提交完整计划；所有段的时段、分配额、课次和冲突统一校验。已有多段时，拒绝旧客户端用扁平 `slots` 覆写；未分段旧数据可继续读取并渐进迁移。
3. 课次生成按 slot 自己的生效日期运行；历史版本、已处理课次、待处理例外、周调整和单节 Adjust 走现有保留与交接逻辑。保存过程用现有课包锁和规则版本校验，失败整笔回滚。
4. UI 在 `RecurringScheduleView.vue` 的既有 Create / Edit 弹窗内增添排课段卡片和预览，不另起第二套排课页面。团课可复用日期段卡片的外观，但 1-on-1 的额度、交接和规则版本逻辑仍留在本业务模块。

实施前需核对旧数据中无限期规则如何确定可编辑未来范围：不得把数据库中的“持续中”直接解释为无限节课；仍由明确分配额限制实际生成。首次转换为多段时必须由用户给出各段的结束日，旧规则历史边界不应被自动截断。

## 6. 验收场景

至少核对：首次单段创建；一次创建三段且段间留空档；每段多个周时段和不同时间；旧规则无修改回显；调整未来段同时保留已完成/待审核/单节 Adjust；增加和减少分配额；尾课不足完整时段；暂停后恢复；Edit receipt 续课后再扩展排课；A 老师已处理、待处理、未来课次并存时交给 B 老师后再 Edit Schedule；并发编辑与旧客户端覆盖保护。每例核对课包余额、分配额、生成课时、lesson records 时间线、老师操作权和日历，不只检查保存接口成功。
