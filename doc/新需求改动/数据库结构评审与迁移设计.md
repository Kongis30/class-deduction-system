## 现有结构盘点

### student

当前表和 `StudentEntity` 已有学生编号、姓名、英文名、性别、生日、来源、状态、校区、备注、主监护人姓名/电话/邮箱/关系。

差距：

- 缺少 `grade`、`school`、`guardian_phone_2`。
- 缺少 pickup/dropoff 勾选和地址。
- `StudentMapper` 目前没有按“学生姓名 + 家长手机号”复用查询的专用方法，Task 2 需要补齐。

本轮迁移：

- 新增当前学生资料字段。
- 新增 `idx_student_name_phone`，支撑报名 intake 识别复读报名学生。

### enrollment_order

当前表和 `EnrollmentOrderEntity` 以 `student_id`、可选 `class_id`、订单状态、经手人、币种、原价、优惠、实收、付款状态和备注为主。

差距：

- 订单没有本次报名的校区、报名日期、周期起止日期。
- 订单没有学生资料快照，学生资料后续被更新会影响历史报名展示。
- 订单没有接送快照、费用明细快照和余额快照。
- 现有模型偏单课程/单班级，不适合一张报名表多行课程。

本轮迁移：

- 新增校区、报名日期、周期、学生资料、接送、费用和余额快照字段。
- 保留现有 `original_amount`、`discount_amount`、`received_amount`，新增 `tuition_subtotal_amount`、`pickup_fee_amount`、`extra_fee_amount`、`extra_fee_detail`、`discount_detail`、`amount_due`、`balance_amount`，兼容历史订单。

### enrollment_order_item

当前没有订单明细表。

差距：

- 无法保存同一报名表下多个 Register Class 行。
- 无法保存每行 Detail、Price、结构化课程选项、手动改价标记、1 对 1 课时和老师。

本轮迁移：

- 新增 `enrollment_order_item`。
- 每行保存 `register_class`、`course_type`、`detail`、结构化选项快照、最终价格、原配置价格、手动改价标记、1 对 1 小时/单位和老师。
- 预留 `course_product_id`、`course_price_option_id`、`class_id`，支撑后续 intake 事务创建课包或班课报名。

### course_product 和 course_price_option

当前 `course_product` 和 `CourseProductEntity` 是课程产品模板，能表达 1 对 1/班课、默认课时、计费模式、默认教室/老师和标价；`course_product_schedule_slot` 保存固定周时段。

差距：

- 不能直接表达客户需要的课程价格矩阵：Register Class、年级/档位、周期/时长、时段、价格、启用状态。
- 现有 `course_product` 继续作为课包/班课生成模板更稳，直接扩成价格矩阵会影响已有逻辑。

本轮迁移：

- 新增 `course_price_option`，作为报名页结构化选择器的数据源。
- 可选关联 `course_product_id`，让价格选项在后续后端实现时能映射到现有课包或班课模板。

### course_package

当前表和 `CoursePackageEntity` 是报名后生成的独立课时账户，已有订单、学生、课程产品、名称/科目/授课模式快照、总单位、默认单节单位、已用/剩余单位、金额快照和预计结束日期。

差距：

- 多课程订单下，仅靠 `enrollment_order_id` 和 `course_product_id` 难以稳定定位来源明细，尤其是同一订单多行相同产品时。

本轮迁移：

- 新增可空 `enrollment_order_item_id`，兼容历史课包，并支撑后续 intake 逐行生成课包。

### class_group 和 class_enrollment

当前 `class_group`/`ClassGroupEntity` 表达班课主数据；`class_enrollment`/`ClassEnrollmentEntity` 表达学生进入班课后的在册记录、报名/到期日期、计费快照和状态。

差距：

- `class_enrollment` 没有来源订单明细，后续后台整理难以从某条报名明细追踪到对应班课报名。
- 报名阶段无需教室，本轮不修改 `class_group.classroom_id` 语义。

本轮迁移：

- `class_enrollment` 新增可空 `enrollment_order_item_id`，兼容历史班课报名。

### payment_record

当前表和 `PaymentRecordEntity` 已支持同一订单多条支付/退款记录，保存付款编号、付款方式、类型、状态、金额、支付时间和经手人。

差距：

- 报名 intake 创建多笔付款属于后端事务能力，表结构已基本满足。
- 现有注释里仍有早期“fixed as cash in phase one”表述，后续可在实体/文档清理，不阻塞 Task 1。
- `payment_method` 已有 `OTHER` 字典项，满足 Others 进入字典的确认结论。

本轮迁移：

- 不新增付款表字段。

### receipt_record

当前表和 `ReceiptRecordEntity` 已有 `receipt_payload` JSON 快照。

差距：

- 新收据样式、Show EIN、政策文本、Zelle 二维码等属于 payload 内容和后端/前端打印逻辑，表结构可承载。

本轮迁移：

- 不新增收据表字段。
- 后续实现应在 `receipt_payload` 内保存完整打印快照，同一收据切换 EIN 不新增记录。

### lesson_record

当前表和 `LessonRecordEntity` 已有计划/实际老师、教室、时间、课时单位、扣课、老师确认、管理员确认、拒绝原因和来源。

差距：

- Task 7 需要查询和展示 1 对 1 消课表，但 Task 1 不需要改 lesson_record。

本轮迁移：

- 不新增消课字段。

## 迁移脚本

新增脚本：

- `doc/migrations/20260715_registration_intake_schema.sql`

执行顺序：

1. `student` 增加报名表当前资料字段和学生复用索引。
2. `enrollment_order` 增加报名、学生、接送、费用和余额快照字段。
3. 创建 `course_price_option`。
4. 创建 `enrollment_order_item`。
5. `course_package` 增加可空 `enrollment_order_item_id`。
6. `class_enrollment` 增加可空 `enrollment_order_item_id`。
7. 执行脚本末尾的 information_schema 验证查询。

回滚顺序：

1. 删除 `class_enrollment` 到 `enrollment_order_item` 的外键、索引和列。
2. 删除 `course_package` 到 `enrollment_order_item` 的外键、索引和列。
3. 删除 `enrollment_order_item`。
4. 删除 `course_price_option`。
5. 删除 `enrollment_order` 新增快照字段和索引。
6. 删除 `student` 新增字段和 `idx_student_name_phone`。

注意：如果已产生新报名数据，回滚会删除新表/新字段中的业务数据，必须先备份或导出。

## 未决风险

- 课程价格矩阵的完整数据仍待客户提供，本轮只提供结构，不填充业务价格。
- 线上课收据税号归属未确认。
- 中途插班手动改价是否只影响当前报名仍需产品确认；当前设计通过 `manual_price_override` 和 `original_price_amount` 保留差异。
- 报名周期是自由起止日期还是固定周期选择仍需确认；当前设计在订单保存起止日期，价格选项保存标签。
- 1 对 1 剩余“2 节课”提醒按小时还是按次数仍未确认，本轮不改 lesson/package 规则。
