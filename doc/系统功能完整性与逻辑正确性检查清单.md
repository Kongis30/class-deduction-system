# 系统功能完整性与逻辑正确性检查清单

## 1. 文档目标

本清单用于检查课程管理与消课系统是否：

- 覆盖机构日常运营所需的关键业务。
- 在正常、异常和边界场景下保持业务逻辑正确。
- 保证订单金额、付款流水、课时余额、排课记录、教师工资和报表数据一致。
- 为管理员、老师、学生提供符合角色边界的操作入口。
- 对尚未确认的业务规则采取保守处理，不隐式生成错误数据。

建议每次重要版本发布前执行一次完整检查。每项可标记为：

- `[x]` 通过
- `[ ]` 未检查
- `失败` 实际行为不符合预期
- `需确认` 缺少产品规则，暂时无法判断
- `不适用` 当前版本明确不支持

## 2. 当前系统的业务职责

### 2.1 核心职责

系统是一个面向补习机构的轻量运营与数据统计系统，核心职责是：

1. 管理课程产品和报名价格矩阵。
2. 完成学生报名、收费、欠费跟踪和收据留档。
3. 将报名结果转换为可履约的 1 对 1 课包或班课资格。
4. 生成和维护学生、老师、教室的课程安排。
5. 记录实际上课结果，通过确认流程完成消课。
6. 根据终确认课次计算老师应付工资。
7. 汇总报名、付款、余额、课时、到期和异常数据。
8. 为管理员、老师、学生提供不同权限的工作入口。

### 2.2 系统不应承担的隐式职责

在规则未明确前，系统不应自行推断或自动实现：

- 部分退款后的课时回滚和教师工资回滚。
- 超额付款自动转为 credit 或预存款。
- 冲刺班完整价格矩阵。
- 班课跨月补课、停课顺延和自动续费。
- 线上课税号。
- 支票号是否必填及其查询规则。
- Excel 导出的固定字段、权限和脱敏规则。

### 2.3 核心业务主链路

系统的核心业务链路是：

`课程与价格配置 -> 学生报名 -> 订单与课程明细 -> 付款与收据 -> 课包或班课资格 -> 排课与教室 -> 消课与课时台账 -> 老师工资 -> Reports`

所有下游数据都应能追溯到上游事实记录。Reports 负责汇总和发现异常，不应成为独立修改业务事实的入口。

## 3. 关键角色

### 3.1 管理员或员工

- 维护学生、老师、课程、价格、校区、教室和支付方式。
- 录入报名、付款并打印收据。
- 创建或调整排课。
- 处理教室后补和冲突。
- 终确认消课。
- 查看老师工资和运营报表。

### 3.2 1 对 1 老师

- 查看自己的课程和学生。
- 提交自己的课次确认。
- 不能查看或确认其他老师的课程。
- 初确认不直接扣减学生课时，也不直接生成应付工资。

### 3.3 1 对 1 学生

- 查看自己的课程安排。
- 查看自己的课程和剩余课时。
- 不能查看其他学生的资料、课包和课程。

## 5. 用户可能提出的业务需求

### 5.1 报名与学生

- 新学生首次报名。
- 老学生报名新课程。
- 一次报名多个课程。
- 修改学生当前资料，但保留历史报名资料。
- 查看学生全部报名表、付款和课包。
- 中途插班、手动改价或明确的 0 元报名。
- 1 对 1 报名时自动创建学生和老师账号。

### 5.2 收费与财务

- 一次付清。
- 报名时使用多笔、不同方式付款。
- 后续补款。
- 欠费查询。
- 打印和回看历史收据。
- 显示或隐藏收据税号。
- 整单取消或整单退款。
- 部分退款、credit、预存款和支票号管理。

### 5.3 排课与履约

- 报名时生成 1 对 1 初始课次。
- 创建固定排课规则并持续生成课次。
- 本周新增、修改或取消课次。
- 老师、学生或教室时间冲突处理。
- 报名时不选教室，后续补录教室。
- 查看统一 Calendar。
- 班课学生中途加入、到期或购买指定课次数量。

### 5.4 消课与课时

- 标准 2 小时消课。
- 1.5 小时等非标准时长消课。
- 老师初确认、管理员终确认。
- 驳回、重新确认或撤销。
- 余额不足时阻止消课。
- 查看课时台账和余额变化。
- 剩余 2 节课时触发续费提醒。

### 5.5 老师工资

- 按老师和日期范围查看可结算课次。
- 不同课程或学生使用不同费率。
- 预览工资。
- 创建并确认工资结算批次。
- 防止同一课次重复结算。

### 5.6 运营统计

- 查看报名金额、已收、余额和付款状态。
- 查看剩余课时、到期和续费提醒。
- 查看取消和退款订单。
- 检查付款流水与订单金额是否一致。
- 检查课时台账与课包余额是否一致。
- 从报表追溯到学生、订单、付款和课包。

## 8. 发布阻断标准

出现以下任一情况时，不应发布：

- 报名事务会留下半成品数据。
- 缺价格可静默生成非预期 0 元订单。
- 超额付款可以入账。
- 同一付款被重复计入多个课包。
- 同一课次可以重复扣课或重复结算工资。
- 老师或学生可以访问其他人的数据。
- 学生、老师或教室冲突未被阻止。
- 订单、付款、课包、台账和 Reports 的核心金额或课时口径不一致。
- 取消或退款订单仍计入有效经营数据。
- 后端全量测试、前端 typecheck 或 build 失败。
