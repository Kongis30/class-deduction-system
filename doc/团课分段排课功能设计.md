# 团课分段排课功能设计

状态：待实现。本文以现有代码为依据，规定同一个实际班级在不同日期区间使用不同课表的行为。所有日期与时间按系统现行的 America/New_York 校区时间解释。

## 1. 目标与范围

同一个 Product → Teaching project → Actual class 可以保存多个排课段。每段有独立的起止日期、每周上课日、时间、老师、科目、教室或线上方式。日期间允许留空档；报名、课次、名册和消课仍归属同一个实际班级。

例如，一个班级可以配置：

| 排课段 | 日期（含首尾） | 上课日期 | 时间 | 课次/课时 |
| --- | --- | --- | --- | --- |
| 1 | 11/21–11/22 | 每天 | 13:00–16:00 | 2 节 / 6 小时 |
| 2 | 11/23–11/25 | 每天 | 16:00–19:00 | 3 节 / 9 小时 |
| 3 | 11/30–12/03 | 每天 | 16:00–19:00 | 4 节 / 12 小时 |

若这些日期均非项目假期，预览应给出 **9 个上课日、9 节课、27 小时**。11/26–11/29 不排课。“每天”在界面上只是一次勾选周一至周日，数据库继续使用现有的星期字段；同一段内仍可安排多个不同的周时段。

本文针对**团课实际班级**。1-on-1 的 Create Schedule / Edit Schedule 有课包分配额、规则版本和老师交接，不能直接套用班级模型；其独立的创建与编辑方案见[1-on-1 分段排课交互设计](./1-on-1分段排课交互设计.md)。

## 2. 现状与需要打通的入口

- `class_group` 保存班级总起止日期，`class_group_schedule_slot` 保存周几、时间、老师、科目、教室、A/B 轮换等，**slot 没有生效日期**。`ClassGroupServiceImpl.generateFutureClassOccurrences` 在班级起止日期内对每一天匹配周几并生成 `lesson_occurrence`。
- 同一个 `PUT /v1/classes/{classId}/schedule` 目前由三个前端入口调用：`GroupCourseModelPanel.vue`、`CoursePriceOptionsView.vue` 和 `ScheduleAdjustmentsView.vue`。三个入口都把一组扁平的 `slots` 全量提交；只改一个页面会让另外两个页面丢失分段信息。
- `GroupCourseModelServiceImpl.getScheduledClassDates`、报名与订单服务通过 `ClassScheduleDates.scheduledDays` 计算可报名日期。该工具目前只取所有 slot 的星期并集，忽略区段。订单中按课次计费的权益截止日也依赖这些日期。
- 项目假期的新增、编辑、删除通过 `ClassHolidayServiceImpl` 同步班级课次、计算顺延日期及重算按课次报名的有效期；每日续排任务 `EnrollmentOrderServiceImpl.renewActiveClassOccurrences` 还有另一条生成入口。这些入口必须使用同一套分段日期判断。
- 班课单节 Adjust 经 `ScheduleAdjustmentServiceImpl` 修改具体课次并写调整日志。历史确认则关联 `lesson_record`。班级课表更新目前会移除未来没有消课记录的课次，不能把人工调整误当成普通模板课次删除。

## 3. 业务规则

1. **一个班级，多段课表。** 排课段只改变排课模板，不创建新的 Actual class、报名订单、课包或收据。老师和教室按具体课次取对应段的 slot，班级级默认老师/教室仅用于兼容旧数据。
2. **段表示完整课表。** 每段日期首尾都包含；同一班级的段日期不能重叠，允许间隔。同段内可有多条周时段；同一天的时段不能互相重叠。新增段可以复制已有段后改日期、时间和资源。
3. **日期受班级范围约束。** 管理员配置的段须落在班级原始起止日期内，不能越过 `schedule_base_end_date`。班级结束日因假期自动顺延的部分按第 6 节处理。更改班级起止日期时，若已有段越界或会影响已开始课次，必须报出具体段并要求先调整课表，不静默截断。
4. **按实际日期生成课次。** 只有日期同时满足班级范围、某段范围、slot 的星期、非假期，才生成课次。每节课时由起止时间按半小时单位计算。同一天有两个时段就是两节课；按课次报名的“上课日”计数仍是去重后的日期，沿用现行业务口径。
5. **历史事实不可重写。** 已开始、已有 `lesson_record`、已确认或处于待审核流程的课次和相关财务记录保留原时间、老师、科目及课时。编辑模板只影响可重建的未来普通课次；保存失败整笔回滚。
6. **单节 Adjust 是例外。** 未处理但已经单节调整的未来课次保留其时间、老师和教室。重建时识别它原本占用的“课位 + 原计划日期”，不再额外生成对应的模板课次；仅按最终实际时间检查资源和学生冲突。若旧数据缺少足以识别原课位的信息，保存前列出该课次并阻止有歧义的修改，不能直接删除或重复生成。
7. **资源冲突按课次判定。** 不同段使用同一老师或教室是合法的，只要实际日期时间不冲突。保存时继续检查老师、教室、在册学生的冲突；报错展示日期、时间、课程/班级和老师，不向用户展示数据库 ID。
8. **A/B 轮换属于 slot。** 旧课表的轮换锚点继续有效；新段默认从该段首个有效上课日开始轮换。轮换次数只统计该 slot 生效区间内实际开课且非假期的日期，不能把段间空档当作上课次数。
9. **空档有意义。** 段间没有课，不能从全部 slot 的星期并集在空档生成课次，也不能把空档日期提供给报名日期选择器。

## 4. Create schedule 与 Edit schedule 交互

实际班级创建后，若尚无排课 slot，入口显示 **Create schedule**；已有排课才显示 **Edit schedule**。两者使用同一段式编辑器，但创建不展示“将删除的课次”，编辑必须展示变更影响。现有三个入口统一按这一状态显示，不能一个入口仍用旧的扁平弹窗。

**Create schedule：**进入后先看到班级原始起止日期和一张空的排课段卡片；日期默认覆盖班级原始周期，用户可以缩短、改日期。每段依次填日期范围、周几/每天、时间，再为每个时段选择老师、科目、教室或线上方式。点 Add period 建空白段，点 Copy period 复制时间与资源但要求重新填写日期；不得自动把前一段无限延续。用户设置完毕先看展开的具体上课日期与节数，再点 Create schedule 一次性保存。

**Edit schedule：**进入后完整回显全部现行排课段，按日期排序；显示每段已发生、已处理、人工调整和未开始课次的数量。过去的段只读；跨越现在的段仅允许修改其未来部分，必要时在生效点拆成历史段和未来段。修改时间、老师或日期、新增或删除未来段后，预览逐项展示保留的例外课次、要替换的普通课次、权益截止日变化和冲突。只有预览通过才能 Save changes；保存后回到原班级，并让 Schedule、报名日期和日历读取同一新课表。

共用界面按时间顺序显示“排课段卡片”，每张卡片有日期范围、周时段选择器、逐时段的老师/科目/教室/轮换设置；保留现有周时段编辑能力。提供 **Add period、Copy period、Remove period**。移动端每段折叠展示日期、课次和课时摘要，展开后编辑，避免同时铺满多个日历。

页面顶部显示班级原始日期范围；段下方给出按实际上课日期计算的预览：各段节数与课时、空档、跳过的假期、受影响的报名权益，以及将被重建/保留的未来课次。保存按钮旁显示“修改从哪一天开始生效”。预览为空、日期交叠或有冲突时不能保存。

| 操作场景 | 预期行为 |
| --- | --- |
| 新班级首次 Create schedule | 初始只有一张空段；日期默认班级原始周期。用户可直接创建单段，也可分拆成多段；保存前看到精确课次。 |
| 原有单一周课表首次 Edit schedule | 显示为覆盖班级原始日期的一段，原有时段和资源完整回填。无修改直接保存，课次结果不变。 |
| 课前新增第二段或复制一段 | 第一段截止日由用户明确调整；两段都在预览中展开成具体课次。不能让旧段继续覆盖第二段日期。 |
| 修改某段的周几、时间、老师、科目或教室 | 只重建该段受影响的未来普通课次；其他段和历史不变；冲突时显示具体日期。 |
| 删除未来段 | 预览列出将减少的课次及受影响的报名权益；若已购课次无法履约则拒绝保存。 |
| 修改跨越今天的段 | 已开始部分只读；仅允许修改尚未开始的课次。必要时由界面在生效时间处分割该段，明确展示保留与重建的边界。 |
| 已有单节 Adjust、待审核或已确认课次 | 单节例外与处理历史保留；新模板不得生成重复课次。若新安排与保留课次相撞，拒绝并提示该课次。 |
| 同日多时段或跨段同星期不同时间 | 同日多个不重叠时段正常生成；不同段的日期不交叠即可使用不同时间和老师。 |
| 修改 Actual class 起止日期 | 对越界段、历史课次和报名权益进行校验；界面引导到 Edit schedule 完成必要调整，不悄悄改变区段。 |
| 点击 Cancel、重复点击 Save、并发保存 | Cancel 不写数据；Save 防重复提交；服务端按班级锁和版本重新校验，过期预览提示刷新。 |

三个班课 Edit schedule 入口统一使用同一段表单/提交模型，避免其中一个旧弹窗把分段课表压回扁平 `slots`。Schedule 页的单节 Adjust 入口继续修改一节课，不改变整个排课段。

## 5. 数据与接口方案

优先沿用 `class_group_schedule_slot`，每条 slot 增加可空的 `effective_start_date`、`effective_end_date`，同一日期范围的 slot 在读写时组成一段；无需新建排课段表。旧 slot 两字段为 `NULL` 时，含义是覆盖班级完整原始周期，读取时包装为单一段。新数据必须同时填写两个日期，不能只填一端。

为保留多次编辑后的单节 Adjust 归属，slot 还需稳定的**逻辑课位标识**：新版本 slot 记录沿用原逻辑课位标识，旧 slot 可按现有 ID 推导。具体字段和迁移在实施时验证外键与软删除策略；历史 slot 不能物理删除，因为旧课次仍引用它。普通课次的原计划日期就是生成日期；单节 Adjust 的原计划日期从第一条调整日志的 `beforeSnapshot` 恢复。历史展示和出勤筛选读取旧 slot 时必须能查到已停用版本，不能只查当前活跃 slot。无法确定归属的旧数据走第 3 节的阻断规则。

`GET /v1/classes` 和 `GET /v1/classes/{classId}` 在现有 `scheduleSlots` 基础上返回按日期归组的 `scheduleSegments`，slot 仍包含老师、科目、教室、轮换等原字段及稳定标识。`PUT /v1/classes/{classId}/schedule` 增加 `segments` 结构，例如 `[{startDate: "2026-11-21", endDate: "2026-11-22", slots: [{weekday: 6, startTime: "13:00", endTime: "16:00", ...}, {weekday: 7, ...}]}]`。旧版 `slots` 只用于尚未分段的班级。若一个班级已有多段，旧客户端提交无日期的 `slots` 必须被拒绝并提示刷新，防止部署期间覆盖新课表。班级的 `scheduleDesc` 改为含日期的简短摘要，不能让旧的纯周课表解析器把它误当作唯一排课来源。

增加只读排课预览接口，复用保存时的日期展开、假期、冲突和报名校验规则。保存时在事务内重新计算预览，锁班级及相关资源，按“保留课次 → 重建可替换课次 → 校验权益和冲突 → 更新模板与课次”的结果原子提交。前端预览不能替代服务端最终校验。

## 6. 上下游影响与处理

| 业务位置 | 现有依赖 | 分段后的要求 |
| --- | --- | --- |
| 班级课次生成 / 每日续排 | 周几匹配整个班级日期 | 共用一个“某日生效的 slot”判断；空档不生成，历史和人工调整保留；不能出现两条生成路径算出不同课次。 |
| 项目假期 | 跳过假期并按原周表顺延，以保全原课次数 | 原定课次数按所有段的实际上课日计算。假期造成的缺口沿**最后一段**的周时段在原周期之后补齐；预览明确显示派生补课日期和有效结束日，不在段间空档偷偷插课。遇到资源或报名冲突则拒绝假期/课表变更。旧单段班级继续原有顺延行为。 |
| 报名 / Edit receipt / Registration plan | `scheduledDays` 提供首课日期及按课次权益截止日 | 日期列表来自各段并去重。新报名或续报必须能在其购买期限内找到足量实际上课日；固定日期方案、月方案仍沿用现有计费价格及月份规则。排课修改不生成新订单、收据或付款。 |
| 已报名学生的权益 | `class_enrollment` 的报名日、截止日决定参与课次与到期提示 | 按课次权益在保存事务内依据保留历史和新课表重算截止日与状态；不足所购课次则拒绝变更。按月权益保持日历期限，不因课表改价或改月份。续课形成的权益段仍归原逻辑课程。 |
| 团课消课 / 教师课表 / 学生日历 / 教室占用 | 读取具体 `lesson_occurrence` | 继续从实际课次展示，不从 `scheduleDesc` 猜时间。已确认课次及工资归属不变；未来课次按新段的老师、教室和科目显示。 |
| Data Summary / roster / period / 续费提醒 | 报名权益与实际班级、课次日期 | 仍是同一个班级与报名记录；仅按课次权益截止日等实际受影响字段变化。段间空档不产生第二条报名或第二张收据。 |
| 单节 Adjust / A/B 轮换 | `schedule_slot_id`、调整日志和 slot 轮换锚点 | 保留单节例外及其原模板占位；更新模板后不回写历史科目/老师，轮换不计算空档或假期。 |
| Product 归档 / 删除班级 | 按实际班级停止未来课次 | 所有段同属一个班级，沿用现有归档和删除范围；清理未来课次时不遗漏任何段。 |

假期自动顺延属于现有业务承诺，因此最后一段要作为延长段的时间模板；这部分是**系统派生排课**，在预览和班级有效结束日中可见。若业务希望“到指定结束日绝不顺延”，应另立规则，不在本功能中悄悄改变现有假期语义。

## 7. 实施顺序与验收

1. 加日期字段与逻辑课位标识，保持旧单段数据可读；先统一后端的有效日期判断及课次预览，再改所有生成、假期和报名计算入口。
2. 实现事务性保存：区分历史、已处理、人工调整与可重建课次；校验资源冲突和已购权益。旧数据无法安全识别人工调整时明确阻断。
3. 更新三个 Create schedule / Edit schedule 入口与共用表单、班级信息日期校验、课表摘要及预览；服务端拒绝旧客户端覆盖多段课表。
4. 分别核对课程报名、Edit receipt、团课消课、假期顺延、每日续排、日历/教室占用、Data Summary 和 roster 对同一班级的显示。

验收至少覆盖：本文 9 节/27 小时示例；段间空档；同日多时段；跨段换老师/教室；单节 Adjust 后再编辑课表；待审核/已确认历史；新增/撤销假期；按课次与按月报名及续报；班级日期缩短；旧单段数据回显和旧客户端防覆盖。每例核对生成课次、权益截止日、报名记录数量及课次时间线，不只检查保存接口返回成功。
