# Checklist

- [x] 已完成长期需求缺口清单，并按已完成、部分完成、未完成、需确认分类。
- [x] 已按用户频率和数据风险标记 P0、P1、P2 优先级。
- [x] 已明确第一阶段优先修复金额、余额、课时、报表一致性问题。
- [x] 已明确 Students、Orders、Reports 的取消、退款、已收、余额统计口径。
- [x] 已明确多课程订单后续补款对订单级和课包级金额的语义。
- [x] 已提供 Reports 一致性检查方案，覆盖付款流水与订单金额、课时台账与课包余额。
- [x] 已明确老师工资统计闭环，包括时间范围、终确认课次、学生/课程费率和应付金额。
- [x] 已明确教室后补闭环，包括待补列表、冲突校验和 Room Calendar 复查。
- [x] 已明确排课冲突详情结构，包含冲突资源、冲突时间和已有课次入口。
- [x] 已明确报名初始 1-on-1 课次需要校验学生时间冲突。
- [x] 已把部分退款、credit、冲刺班、班课复杂运营、Excel 导出、线上课税号、支票号归入产品确认队列。
- [x] 已定义未确认规则前的保守处理原则，不隐式实现复杂业务。
- [x] 已定义每次迭代的用户体验检查：入口、下一步、错误修正。
- [x] 已定义每次迭代的工程质量检查：代码简洁、逻辑清晰、最小必要改动。
- [x] 已定义每个阶段的最小测试和人工验收范围。
