# Checklist

- [x] 已明确分期付款的订单级权威金额和付款流水规则。

- [x] 已确认多课包订单后续补款不会重复累计到每个课包实收金额。

- [x] 已验证实际课时短于、等于、长于计划时，余额、台账和未来排课保持可解释一致。

- [x] 实际课时无法平衡未来排课时，用户得到明确错误和下一步，而非静默失败。

- [x] 已验证 Formal Leave、No Show、取消、补课和驳回对课时、排课、工资资格的影响。

- [x] 当前 Full refund 的范围、数据变化和用户确认提示明确且可追溯。

- [x] 部分退款、按课程退款、已消课退课和 credit 被明确标记为未实现或已实现能力，不被伪装为 Full refund。

- [x] Registration、Receipt 和退款对话框中的退款政策与系统可执行能力一致。

- [x] Students、订单详情和 Reports 对 CANCELLED / REFUNDED 订单采用一致统计口径。

- [x] Reports 能发现 payment_record、订单金额、课包余额、课时台账之间的差异，并提供钻取入口。

- [x] 付款、实际课时、退款、排课冲突和报表差异都有用户可执行的下一步。

- [x] 已补充或明确缺失的后端测试、前端/E2E 验收场景。

- [x] 后续实现任务按数据风险和用户频率排序，未定义规则需要产品确认后再开发。
