# Edit Schedule 易用性改造实现计划

> 状态：实施中。当前先落地后端同周期额度调整和未来课次老师交接；预览交互与编辑窗口精简仍待实现。未修改线上数据。
> 范围：1-on-1 课包的 Edit Schedule 窗口及其保存链路。课时口径以 [1 对 1 课时业务规则](./one-on-one-hours-business-rules.md) 为基础；2026-10-28 用户明确更正：仅更换已有 slot 的固定老师沿用原周期。其他文档若仍写“换老师建立新周期”，以本次确认的要求为准，实施时再同步修订。

## 1. 目标与现状

### 当前实施进度

- 后端已开始将“只改已有 slot 分配额度”与长期改排课分开：保留规则 ID 和周期起点；增加额度时补齐末尾普通课，减少额度时只回收未开始、无记录的末尾普通课。历史／待处理／人工调整课无法安全回收时阻断保存。
- 换老师时，1-on-1 Lessons 应通过同一 slot lineage 展示完整时间线；已处理课次和原老师快照不改，未来无 lesson record 的有效课次改为新老师，保留其单次时间、教室和课程名称。仅换老师沿用原周期是最新业务要求，不能据此认为现有代码已经满足。
- Edit Schedule 窗口尚未完成计划中的紧凑摘要、增减课时输入、差异预览和二次确认。当前阶段先修正保存语义和提示，后续按第 4 节继续。

管理员常见的两类需求是：沿用现有每周时段，给某位老师补充或收回尚未使用的课时；从某个日期起改变固定上课安排，重新安排未来课程。用户应直接说明想改变的老师、时段和课时，不应为了增加 2h 而重填所有老师的剩余分配额，也不应猜测保存会否重置老师的消课统计。

当前 `RecurringScheduleView.vue` 的 Edit Schedule 把 Start Date、Status、Notes、整张周历及每个 slot 的 `Schedule total` 一起展示。`Schedule total` 包含本周期已消课与未处理课时。后端已有仅调整现有 slot 额度的同周期路径，但保存下限校验仍按同一规则编号累计各周期已消课；旧规则复用编号时会把旧周期消课误算进当前周期，导致 Bowen Deng 增加 0.5h 被拒。窗口也尚未清楚区分“原计划增减课时”和“重新排课”的提示。另有 Adjust Schedule 窗口处理单周/单课临时变化，不应在 Edit Schedule 中复制该能力。

本次改造的原则：**一个 Edit Schedule 入口、一个保存预览、由系统识别影响范围；后台对不同业务操作使用明确的写入路径。**管理员不需要选择“周期版本”等技术概念。

## 2. 用户在窗口中的操作

### 2.1 默认视图：看清现状，快速改剩余课时

窗口标题为 `Edit Schedule`，副标题显示学生、课包和当前固定上课安排。顶部只放三项与本次决策有关的课时：

| 指标 | 展示含义 |
| --- | --- |
| Package remaining | 课包账本剩余课时；不能直接等同于可新增排课时。 |
| Committed hours | 当前老师尚未最终消课的分配，加上不包含在这些分配内的其他规则预留与保留例外课次；同一课时只计一次，详情可展开。 |
| Available to add | 课包剩余扣除去重后的占用，本次可以追加到现有安排的课时；由后端计算，异常或负差异不默默归零。 |

下方按现有 slot 列紧凑行：`周几 · 时段 / 老师 / 教室 / 该时段已扣 / 该时段剩余 / 最后一节预计日期`。同一老师负责多个时段时，老师汇总只在顶部或展开详情中显示，避免把老师余额重复放在每一行。点击一行展开编辑，默认只突出两个操作：

- `调整未来课时`：输入相对变化量，例如 `+2h` 或 `-2h`；旁边即时说明预计增加/取消几节普通未来课。历史总分配额只读展示，不再让管理员直接改含历史的 `Schedule total`。
- `修改这段安排`：展开当前老师、课程名称、教室等字段。只更换已有 slot 的固定老师时沿用原周期并交接该 slot 的完整记录；修改每周时段等排课定义时进入未来重排。只改名称、教室或备注不会重置周期。

整张 `WeeklyTimeSelector` 默认折叠在 `修改每周上课时间或新增时段` 中。需要改长期上课日程时再展开；手机端先显示时段列表，周历作为编辑工具而不是首屏主体。Start Date 仅在“重新安排未来课程”时改名为 `生效日期` 并出现；原规则的起始日期在普通补课时只读。Status 从此窗口移出，停课/恢复沿用独立入口；Notes 折叠为可选项。

若管理员要改某一节或某一周，窗口提供 `仅调整单节/本周` 跳转现有 Adjust Schedule，并保留当前学生与课包上下文。该入口不修改固定周规则或老师分配额。

### 2.2 系统识别保存方式，预览说明后果

| 用户改动 | 窗口给出的结果 | 保存行为 |
| --- | --- | --- |
| 只改课程名称、教室或备注 | “更新未来课程资料；课时和已上课程不变” | 沿用当前周期，仅更新适用的未来课次。 |
| 固定时段与老师均不变，只给现有 slot 增减未使用课时 | “继续当前安排；预计新增/取消末尾普通课次” | 沿用当前周期，增减该 slot 的分配及其未开始的普通课次；历史 Deducted 不清零。 |
| 仅更换已有 slot 的固定老师 | “沿用当前安排，由新老师接手该时段及完整课程记录” | 沿用当前周期和 Start Date，按第 2.3 节交接历史查看、待处理操作权和有效未来课次。 |
| 改 Start Date、固定时段、单课时长，或新增/删除 slot | “从生效日期起重排未来课程” | 建新周期，按新安排生成未来课次；若同时更换老师，还须执行下文的记录交接。 |
| 临时改一节或一周 | 引导至现有 Adjust Schedule | 不改固定规则和周期分配。 |

底部固定显示差异预览，而不是笼统的“将重新生成课程”提示。至少列出：保存方式、生效日期、每位老师课时变化、将新增/取消的未来普通课次数与起止日期、保留的已开始/待处理/已调整课次，以及冲突或无法排满的原因。默认不展开逐节清单；点击数量可查看具体日期。按钮使用 `Preview changes` → `Confirm & save`，无改动时禁用。

预览的计算和正式保存必须共用同一业务规划器；保存时重新校验数据版本与资源冲突。预览后如有其他管理员消课、改排课或修改课包，拒绝旧预览的提交并提示刷新，不能静默保存不同结果。

### 2.3 更换某个 slot 的老师：整段课程记录交接

管理员把一个现有 slot 的固定老师由 A 改为 B，表示 B 从此接手**该 slot 对应学生和课包的完整 Lesson records 时间线**，不只是接手新生成的课。若 Start Date、slot 的周几、时段和单课时长等排课定义不变，仅更换老师必须保留原规则、Start Date 和周期边界。交接只覆盖被修改的 slot；同一课包其他 slot 的老师与记录不受影响。再次从 B 改为 C 时，C 接手 A、B 到 C 的同一条时间线。

| 课次类别 | 新老师 B 的 1-on-1 Lessons 中如何显示 | 课次 teacher 字段与历史 |
| --- | --- | --- |
| A 已最终消课的课次 | 原记录原封不动地显示在 B 接手的课程记录列表中，保持原日期、时长、状态和处理结果。 | 仍写 A；不改记录 ID、消课流水、实际授课老师、原周期和额度归属，不重新扣课。 |
| 已开始但尚未最终处理的 A 课次 | 同样随完整时间线交给 B 查看和继续处理，页面清楚标出该节原老师 A。 | 保留原老师、已有提交和原周期快照；B 接手未完成课次的操作权，最终审核仍按原课次及课包账本处理。 |
| 尚未上课、没有老师提交或管理员处理记录的有效课次 | 全部进入 B 的课程记录与后续课表。 | 该课次的计划 teacher 和后续处理归属改为 B，原周期不变；新生成的课次也写 B。若曾单独调整时间、教室或课程名称，保留这些调整；若曾明确指定另一位代课老师，保存前点名提示该指定将被 B 覆盖。 |

已取消课次保留审计记录，不作为待迁移的有效未来课次。未来日期但已经存在提交/审核记录的异常情况，不能静默改写老师；指出课次并要求先处理记录或明确阻断保存。交接不复制记录，也不通过把历史 `teacher_id` 批量改成 B 来实现：1-on-1 Lessons 按 slot 的交接关系展示完整时间线。A 不再是该 slot 当前负责老师入口；如果 A 还负责同一课包的其他 slot，应保留那些 slot 对应的入口。历史已上课记录仍可从课包历史和审计中查询。

交接影响应清楚列出：`历史记录移交查看 N 节（授课老师不变）`、`待处理课次移交 N 节`、`未来课次改为 B N 节`，并指出被覆盖的单课代课安排。课包 Total、Starting、Remaining、slot 分配总额和已确认消课不因只换老师而改变；已确认课时不能重新变成剩余额度或被重复扣减。2026-10-28 用户确认：B 接手该 slot 的整个本周期账目，原 slot 分配 8h、已消 6h、剩余 2h，交接后 B 的该 slot 汇总仍为 8 / 6 / 2h；历史课次的实际授课老师仍显示 A，实际授课记录和历史流水保留原事实。页面应说明已消课数是接手时段的周期汇总，避免误认为这些课都是 B 实际教授的。

## 3. 业务边界与异常处理

1. **同周期增减课时仅处理一个或多个已有、固定定义不变的 slot。**增加时从该 slot 最后一节有效普通课之后顺延生成，不移动原有普通课、人工调整课或补课；减少时仅从末尾移除或缩短尚未开始、没有消课记录的普通课，调整后的分配额不得低于本周期已扣课时与必须保留的占用。不得删除或缩短已开始、老师已提交、待管理员处理、已确认、人工调整或正式请假补课。若可回收课时不足，明确报出可减少上限。
   - 仅修改额度时保留原规则 Start Date 和 `allocation_period_started_at`，不重置当前周期的老师 Deducted；课包总额和账本余额不因分配操作改变。只调整用户指定的 slot，其他 slot 和老师的分配保持原值。
   - Start Date 已经过去，并不妨碍对原周期增减分配：例如原 Start Date 是 9 月 28 日，过了一个月才发现少分配 0.5h，直接给指定 slot 增加 0.5h，Start Date 仍为 9 月 28 日，周期边界保持原值。不得因为日期在过去而要求修改 Start Date、创建新周期或重排已发生课次。Start Date 与内部周期边界各自保留原值，不假定它们必须相同。
   - 以 0.5h 为最小单位，新增 0.5h 时在该 slot 末尾安排 0.5h 的普通课次；减少 0.5h 时从末尾可安全调整的普通未来课次回收 0.5h。若末节原为 2h 且无处理记录，可保持该节日期、开始时间，将其缩短为 1.5h；若不能安全回收，指出具体课次和原因，保存全部回滚。
   - 校验当前分配与当前周期已扣课时使用同一周期边界；旧周期已确认课时已经体现在课包账本中，不得再次计入当前周期已扣或最低分配额。旧周期仍未最终处理且占用余额的课次需单独核对和预留，不重复计入当前 slot 分配。
2. 新增课时必须来自真正未分配且未被其他规则、待处理课次或保留例外占用的额度。课包 `Remaining`、老师 `Remaining with`、未来普通课合计分别展示，不能互相代替。课时以 0.5h 整数单位计算；尾节不足常规单课时长时，沿用现有尾节规则，并在预览中显示实际时长。
3. **只改已有 slot 的固定老师是同周期交接。**沿用原 Start Date、周期边界、该 slot 分配总额和已消课事实，按第 2.3 节把完整历史与未处理操作权交给新老师，并交接符合条件的有效未来课次。修改 Start Date、周时段、单课时长或增删 slot 才按新周期重排；如一次操作既换老师又修改上述排课定义，建立新周期并同时执行记录交接。页面明确说明本次变化和受影响课次。
4. 生效边界采用 `America/New_York` 的业务日期与时间。已开始、已记录或需保留的例外课次按现有规则保留；普通未来课次才可替换。更换老师时，未上课且无处理记录的人工调整课保留其时间等单课调整值，但 teacher 按第 2.3 节交接。跨夏令时、校区/教室与老师冲突、课包结束日期、暂停状态及共享私教组参与人，均由服务端在预览和保存时校验。不能为了凑平数字擅自改变课包余额、Starting Hours 或历史消课。
5. 暂停课包后，未来课次及旧计划按现有停课规则取消；恢复后仍需显式创建新计划，不通过 Edit Schedule 自动复活原安排。没有有效规则的课包继续使用 Create Schedule。
6. 对历史余额与老师分配不一致的课包，显示差异和可核查信息；若无法可靠计算可追加额，阻止自动追加并提示人工核对。不得通过截断负数或暗改分配额掩盖异常。

## 4. 最小实施路径

1. **统一读取与预览口径。**在现有规则详情旁返回当前课包、老师与 slot 的课时摘要，包括已扣、未处理、普通未来课和可追加课时。复用现有排课/课包计算，不在前端根据可见未来课次数猜余额。将前后端的改动分类和课次规划收敛到同一服务层；预览只计算、不写库。
2. **实现同周期增减的窄写入路径。**增加/减少现有 slot 的未用课时，保留规则 ID、`allocation_period_started_at` 和已确认历史；事务内锁定或校验相关课包/规则版本，更新分配额、生成或安全移除末尾普通课次，并记录操作者、变化量和受影响课次。与现有“重排未来课程”的写入路径分开，避免给现有 `PUT /rules/{id}` 的所有调用偷偷改语义。
3. **区分同周期老师交接与新周期重排。**仅更换已有 slot 老师时，保留现有规则与周期，更新符合条件的未来课次 teacher，以及 1-on-1 Lessons 按 slot 交接关系读取完整历史的关联；历史课次和消课流水保留原事实。修改 Start Date、时段、单课时长或增删 slot 时走重排路径，明确生效日期和保留／重建的课次；同时换老师时还需完成交接。前后端按同一规则分类，由后端再次验证。
4. **改造窗口。**先实现紧凑摘要与 slot 行内课时调整，再把周历、备注和重新排课字段按需展开；保留 Adjust Schedule 的单周入口。删除旧的“改 `Schedule total` 即隐式重排”的表单提示和重复分支，保持一个明确的数据模型与保存入口。
5. **同步业务文档与排课历史展示。**实施时更新 [现有课时业务规则](./one-on-one-hours-business-rules.md) 中与本次确认冲突的旧表述；确保 1-on-1 Lessons、Schedule 详情及打印历史都能区分同周期课时调整、同周期换老师与新周期重排。

## 5. 验收场景

- **Zhen Shen Zou：**课包 Remaining 16h，Lau 剩余 4h、Derek 剩余 10h、未分配 2h。在 Derek 行输入 `+2h` 后，预览仅多一节 2h 普通未来课；保存后 Derek Allocated 18→20h、Remaining with 10→12h、Deducted 仍为 8h；Lau 及课包账本不变，周期不重置。具体新增日期以资源/假期校验后的预览为准。
- 给现有 slot 减少 2h：只移除末尾符合条件的未来普通课，老师分配和剩余同减 2h，课包 Remaining 不变，2h 回到未分配额度；如末尾课已有记录，保存被阻止并指明原因。
- Bowen Deng：当前周期分配 8h、已扣 6h、课包剩余 2.5h；旧周期另有已扣 10h。给任一现有 slot 增加 0.5h 后，分配 8.5h、老师剩余 2.5h，原 Start Date、周期边界和课包余额不变；旧周期 10h 不得导致保存被拒。实际新增课次须覆盖 0.5h，并检查学生、老师和教室冲突。
- 原 Start Date 为 9 月 28 日，用户一个月后才给已有 slot 补分配 0.5h：保存沿用原 Start Date 和周期边界，在该 slot 后续安全排入 0.5h，不重建周期、不重排历史；日期已过去本身不能成为保存失败的理由。
- 从未开始且无记录的 2h 末节减少 0.5h，末节保留原日期和开始时间，时长变为 1.5h；若末节已开始、已提交、是人工调整或补课且没有其他可安全回收课时，则说明原因并阻止保存。
- 只修改 Start Date 时建立新周期；仅修改现有 slot 的分配额时不建立新周期。两者都保留已确认历史，并按各自业务规则处理未完成课次。
- 只改教室或课程名称：已发生课程、分配额与老师 Deducted 不变；未来适用课次同步更新。
- 只更换某个 slot 的老师 A → B：规则 ID、Start Date 和周期边界保持原值；该 slot 原分配 8h、已消 6h、剩余 2h，交接后 B 的该 slot 汇总仍为 8 / 6 / 2h。B 的 1-on-1 Lessons 显示该 slot 全部已处理、待处理和未来课次，B 可操作未完成课次。历史课次仍显示原老师且消课数据不变；符合交接条件的未来课次显示 B，其他 slot 不受影响。A 若还有其他 slot 仍保留相应入口；多次 A → B → C 交接仍显示完整时间线，不重复统计已扣课时。
- 同时更换 slot 老师并修改该 slot 时段：按新周期重排，同时让新老师接手该 slot 的历史和待处理记录；课包余额与已确认消课不因换老师重复变动。
- 只改固定每周时间：预览旧课次保留/取消、新课次和新周期老师额度；保存后旧历史记录不改，新的未来安排按生效日执行。
- 单节代课或某周停一次课：通过现有 Adjust Schedule 完成，Edit Schedule 的固定规则与分配统计不变。
- 两位管理员同时修改、课包暂停、余额不足、资源冲突、夏令时边界和无法排满的尾节：明确提示具体阻断原因，不产生半套课次或静默改账。
