# Package Hours 修改：业务与交互测试计划

## 目标与范围

检查 Schedule → Package hours 的 Starting Hours 修改，及其对课包余额、课次、排课和 1-on-1 记录的影响。失败时必须说明是否保存、原因和下一步；不能破坏历史记录或留下部分更新。此计划不等同于整个系统的回归测试。

## 测试场景

| 场景 | 检查要点 | 当前验证 |
| --- | --- | --- |
| 正常增加、减少起始课时 | 提交数值就是最终保存的 Starting Hours；余额按已消课重新计算，预览与结果一致 | 服务层自动测试；浏览器模拟接口测试 |
| 不修改、非法值和边界值 | 未修改不能保存；数值限制在允许范围，按 0.5 小时递增；已有消课和待审核课次不能被透支 | 服务层自动测试；界面输入约束 |
| 普通未来排课、多个时段 | 余额变化后重新核算未来课次，保留已确认历史和原有时段关联 | 排课服务自动测试 |
| 余额调整为零 | 普通未来课次取消，课包完成；明确事先提示影响 | MySQL 事务集成测试；浏览器模拟接口测试 |
| 未完成、已调整、补课、已驳回课次 | 不静默删除；提示具体课次及到 1-on-1 处理 | 排课服务自动测试；MySQL 验证未完成课次阻止保存和回滚；浏览器验证提示 |
| 多学生共享课 | 不影响其他学生的课次；提示先检查共享排课 | 排课服务自动测试；浏览器模拟接口测试 |
| 老数据无法安全匹配 | 不猜测或转移历史；告知需要协助处理 | 排课服务自动测试；浏览器验证提示 |
| 老师、教室或学生冲突 | 保留冲突信息并引导到 Edit Schedule 检查 | 排课服务自动测试；文案检查 |
| 页面打开后课时或课次被别人修改 | 版本不一致时拒绝保存，要求刷新；禁止重复提交旧数据 | 服务层和 MySQL 事务测试；浏览器模拟接口测试 |
| 网络异常或保存后刷新失败 | 区分“不确定是否保存”和“已保存但页面未刷新”，提示刷新核对；防止重复提交 | 浏览器模拟网络异常；代码检查保存后刷新失败分支 |
| 操作过程和移动端 | 保存中禁用输入及关闭操作；提示位于窗口内、可读且不横向溢出；失败时保留输入以便修改 | 浏览器测试 390px 宽度、失败和重试；代码检查保存中状态 |
| 并发死锁、真实线上旧数据 | 验证同时审核课次和修改课时的锁竞争及线上具体历史数据 | 尚未完成真实并发及线上数据验证；数据库事务发生异常应整体回滚，用户需刷新核对 |

## 测试方式和限制

- 后端：排课服务测试、课包服务重点场景，以及在隔离的本地 MySQL 上用合成数据验证真实事务、版本检查、回滚和成功提交。
- 前端：Playwright 使用模拟接口检查对话框、状态变化、提示和移动端布局；不代表真实服务器端到端测试。
- 全量课包服务测试中已有三个与本次修改无关的基线失败，已对照干净版本确认；本次只报告相关测试结果，不将全套测试标记为通过。
- 测试使用隔离数据库与合成数据，没有修改线上学生数据。上线前仍应使用受控测试账号进行真实接口和并发验证。
