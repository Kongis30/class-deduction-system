## 实施顺序与每一步的完成条件

按照先统一口径、再修改状态和写入、最后接入页面与验收的顺序实施。上一项完成并通过其回归后再进入下一项；后端接口可以直接调整，不为旧请求额外叠加兼容分支。以下是实施目标，不能视作已经完成。

### 第 1 步：固化周期和课时口径

1. 沿着 Schedule 详情、Edit Schedule 保存、1-on-1 六字段、单课消课及自动续排，列出当前读写的数据来源和调用点，统一使用同一套周期边界及额度口径。课包账本和 slot 分配属于不同层级，分配变动不能直接改课包余额。
2. 核对当前已加的「新规则明确记录周期起点」是否覆盖全部新建和重排路径，并验证按纽约时间计算，防止日期与实际生效时间混用。同周期的额度、老师、名称和教室调整不得重设该边界。
3. 检查空周期边界的历史规则及现有回退逻辑。输出只读审计列表，记录证据和影响；证据不足时禁止猜测、批量回填或修改老师分配额。涉及线上数据另行制定逐条处理方案。
4. 完成条件：同周期增减 0.5h、新周期、旧周期延迟确认消课的六字段及预留占用有自动化测试；真实隔离库复核 Bowen 数据和课时账本，页面数字与后端一致。

### 第 2 步：重构现有操作的保存链路

1. 把「调整当前排课」和「调整固定排课」分别定义为明确的后端操作及请求，前端只提交对应视图的数据。服务端仍须验证用户提交的操作类型与实际变化一致，不能由前端决定账目是否安全。
2. 当前排课只允许改既有 slot 的老师、额度、名称和教室；同一次操作可以组合这些变化。新增或减少额度只影响指定 slot 的可调整未来普通课次；历史、人工调整课和已有处理记录按既定规则保留。仅换老师自动交接该 slot 的时间线和操作权，不建立新周期。
3. 固定排课改起始日期、周时段、时长或 slot 数量时走新周期链路。新周期中，用户输入的新 slot 额度不得被历史继承隐式覆盖；同一历史来源只能指定一个继承者。
4. 统一保存前校验、冲突检查和事务边界，清理被替代的旧表单分类、临时兼容分支和重复实现；不能为了接口简化改变暂停、恢复、单课调整、续排等其他操作的语义。
5. 完成条件：仅换老师、仅改额度、两者组合、多个 slot、不合法变更和保存失败回滚，均通过服务层和隔离库测试；A 不再负责其他有效 slot 时，其入口消失，其他 slot 不受影响。

### 第 3 步：按起始日期立即重排

1. 保存时立即结束旧周期，替换旧规则尚未开始的普通未来课，并从所选 Start Date 开始生成新周期课次。起始日之前可以没有普通课，不设计待生效状态或延迟切换。
2. 已确认历史保持原事实；已开始的未处理课提示用户先处理或明确撤销回收。人工调整课及补课等例外按既有保留、交接及额度规则核对，不能静默删除或重复分配。
3. 用户按旧 slot 指定新 slot 的历史继承者；新周期老师统计从新周期开始，课包余额只随实际消课变化。事务内校验余额与资源冲突，失败完整回滚。
4. 页面清楚说明保存会立即结束当前固定排课，选未来 Start Date 可能出现没有普通课的间隔。移除未来日期临时阻止代码。
5. 完成条件：隔离库按 11/07 示例验证旧规则未开始的普通课立即替换、新课不早于 11/07、历史和账本不变；检查待处理与保留例外、六字段、冲突回滚及实际页面提示。

### 第 4 步：交接、异常和周边业务联测

1. 同周期 A→B→C 交接，以及新周期一拆二、二合一、多 slot 同老师等场景，核对历史只显示在指定继承关系下、实际授课老师和扣课流水不变。无 slot 的历史课次由管理员明确指定继承它的当前 slot，持久化并统一列表、详情和权限；不可按老师或时间猜测。待处理课在继续修改后按已确认规则回收，不能在交接中再次出现。
2. 测试正式请假、补课、人工调整、待老师和待管理员处理、共享课包、多学生、暂停与恢复、自动续排、单节 Adjust 及冲突；逐课比较日期、时长、老师、状态、分配和课包余额，不只检查接口成功。
3. 核查 `schedule-student-groups.spec.ts` 的失败是测试口径还是业务缺陷；再根据实际业务修正。提示信息要说明具体可操作原因，排课冲突展示课程、日期、时间、老师和学生，不暴露内部 ID。
4. 完成条件：真实数据库 API 测试及桌面、移动端浏览器流程通过；并发和异常中断均无半套数据，测试报告保留实际结果及未覆盖范围。

### 第 5 步：整理、提交与部署

删除不再使用的临时保护、旧请求分支及重复说明，更新需求、测试和数据审计文档；确认工作区变更范围并执行完整回归。只有以上核心场景通过后才标记修复完成。提交与部署按用户当时的要求进行；发布后核对前后端版本、迁移与只读健康检查。

## P0：课时和课次正确性

### 1. 固定排课立即重排

以第 3 步的最新用户要求为准：保存时结束旧周期，所选 Start Date 是新课生成的起点，而不是旧规则的延迟结束日期。课次、额度、历史交接和失败回滚须一起验证。

### 2. 统一六字段与额度校验

- 课包 Total、Starting、Remaining 分别采用现有课包总课时、用户设置的起始可用课时、课包账本未消课时；单纯分配和换老师不得改变课包账本。
- 老师 Allocated、Deducted、Remaining 采用当前周期分配、当前周期确认消课、前两者之差。新周期只统计该周期；历史课次仍按继承关系显示。只换现有 slot 老师时同周期转交账目，例如 8 / 6 / 2h 保持 8 / 6 / 2h。
- 将页面摘要、保存校验、1-on-1 和自动排课所用的周期边界、已扣及保留占用逐一对照；核对 0.5h 增减、已开始/待老师/待管理员的课次、人工调整和补课，防止重复计数与超额。
- 对历史周期边界缺失的规则，先只读列出受影响数据并结合规则、排课历史和消课流水审计。仅在证据足以确定边界时提出逐条修复方案；不能以创建时间或当前时间猜测批量回填，也不能擅自调整老师额度。
- Terry 的快照显示老师剩余额度合计比课包多 2h，原因链仍需结合历史审计确认。隔离库的 50→48h 试验只是验证，不能据此自动修改线上数据。

### 3. 交接与历史完整性

- 仅修改现有 slot 老师：沿用当前周期，自动把该 slot 的完整时间线和未处理操作权交给新老师，已处理课次仍显示实际授课老师。原老师若不再负责该课包其他有效 slot 或待处理职责，其 1-on-1 入口消失；仍有其他职责时保留对应入口。
- 调整时段形成新周期、拆分或合并 slot：管理员在窗口指定旧 slot 的历史继承者，历史不复制、不重复扣课；未指定或重复指定时明确提示。保存后新周期立即接替旧周期。
- 验证连续换老师 A→B→C、多 slot 同老师、换老师同时增减额度、拆分/合并后再次编辑，以及待老师处理、待管理员处理、已确认和人工调整课次；逐项核对课次、操作权、六字段及审计记录。

## P1：完整流程与用户反馈

1. 用真实数据库和浏览器检查两个窗口：只调额度、只换老师、名称/教室调整、固定时段重排、拆分 slot 和历史继承。字段错误标明具体 slot 和调整方法；额度不足、冲突和不可安全回收课次应指出原因及相关课程，避免显示内部 ID。
2. 验证管理员选择先处理旧课或继续重排时的结果。继续时按照已确认的规则回收未处理旧课；不得删除已确认记录或误动其他 slot。
3. 检查共享课包、多学生、多老师，以及单节 Adjust、续排、暂停/恢复、余额变化和打印等相邻流程；失败操作检查事务回滚。核对桌面与手机的显示和操作。
4. 查清 `schedule-student-groups.spec.ts` 的失败是测试口径过时还是页面缺陷，再按业务实际修正，不能仅为了通过而改断言。预览与保存是否有并发版本保护也需核查并补齐必要的保护。

## P2：验收和发布

1. 保留复现步骤和明确预期：每个用例都核对实际课次日期、时长、老师和状态，课包及老师六字段、历史时间线、入口和操作权；报告区分模拟测试、隔离真实数据库及页面测试。
2. 更新现有测试报告和业务文档，删除被新实现替代的临时分支与过时提示；检查工作区其他改动的归属，不将它们混入本次提交。
3. 只有 P0 场景及相关回归通过后才视为修复完成；提交和部署按用户当时的明确要求执行。上线前核对前后端版本及迁移，部署后检查健康状态与关键只读页面，不以线上真实学生作写入测试。
