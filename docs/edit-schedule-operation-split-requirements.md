# 私教课包排课操作拆分与历史继承需求

> 状态：实施中。适用于 1-on-1 课包的固定排课及 1-on-1 Lessons。课时字段口径沿用 [1 对 1 课时业务规则](./one-on-one-hours-business-rules.md)。
> 本文更新了此前“所有固定排课改动放在一张表单”的界面设想；仍由同一个 Edit Schedule 入口打开弹窗，在弹窗内选择独立的操作视图。旧文档 [Edit Schedule 易用性改造实现计划](./edit-schedule-usability-implementation-plan.md)保留作历史参考；具体前端方案见 [Edit Schedule 前端设计与实现计划](./edit-schedule-frontend-design-plan.md)。

## 1. 用户目标与入口

管理员仍点击现有的 **Edit Schedule** 按钮，打开同一个弹窗；在弹窗内先选择操作目的。两种固定排课操作使用独立表单和保存流程，不在同一张表单里同时编辑老师、额度、起始日期和整张周历：

| 弹窗内操作视图 | 处理什么 | 对当前排课周期的影响 |
| --- | --- | --- |
| **调整当前排课** | 维护已有 slot 的老师、分配课时、课程名称或教室；不改变周几、上课时段、单节时长或 slot 数量。 | 沿用原规则、起始日期和周期边界。 |
| **调整固定排课** | 改周几、时段、单节时长、起始日期，或增加、删除、拆分 slot。新 slot 可指定老师和历史来源。 | 保存时立即建立新周期并结束旧规则；新课从所选起始日期开始。 |
| **调整单节／单周** | 临时代课、改某节时间或单周安排；从弹窗提供跳转说明。 | 继续使用现有 Adjust；不改固定规则或 slot 分配。 |

暂停、恢复和结课沿用各自入口，不混进上述两个固定排课画面。创建全新排课仍使用 Create Schedule。

## 2. 调整当前排课

画面按现有 slot 展示周几、时段、老师、教室、课程名称，以及该 slot 的已分配、已扣和剩余课时。用户可以只改所需的 slot；未改的 slot 保持原值。

| 操作 | 保存后的业务结果 |
| --- | --- |
| 增加某 slot 的分配课时 | 保持原周期及其起始日期，在该 slot 后续可用日期补齐普通课次；课包账本 Remaining 不因“分配”本身减少。新增额度受课包未分配余额和冲突校验约束。 |
| 减少某 slot 的分配课时 | 仅从末尾安全回收或缩短未来、未开始、没有处理记录的普通课次；已消课、待处理、人工调整或补课不能被静默改掉。 |
| 将已有 slot 的老师 A 改为 B | B 接手该 slot 的当前周期账目、待处理操作权和符合条件的未来课次；`Allocated / Deducted / Remaining` 保持原 slot 口径。历史课次仍记录真实授课老师 A，消课流水和工资事实不变。 |
| 改课程名称、教室或备注 | 只更新适用的未来课次资料；已发生课次、已扣课时和周期不变。 |

仅更换已有 slot 的老师时，该 slot 的完整时间线自动交给新老师，无需再选择是否显示历史。历史实际授课老师、消课流水和工资事实保持原样，未最终处理的课次由新老师接手操作。若 A 不再负责这个课包的其他 slot，也没有其他仍由其负责的有效安排，则 A 的 1-on-1 Lessons 不再显示该课包入口；A 仍负责的其他 slot 不受影响。

2026-10-29 用户明确：不需要未来待生效计划。调整固定排课保存后立即结束旧周期，替换旧规则尚未开始的普通未来课；新周期从用户选择的 Start Date 生成课次。若起始日是下个月，保存日与起始日之间可没有普通课。已确认历史保留，已开始未处理课按用户选择先处理或撤销回收，人工调整及补课等例外继续依现有保留和额度规则处理。按用户指定的继承者交接历史；老师三项统计仅计算新周期。

仅切换老师不建立新周期。例：原 slot 为 `8h 已分配 / 6h 已扣 / 2h 剩余`，B 接手后仍显示 `8 / 6 / 2h`；已完成课程的实际授课老师仍为 A。

如果历史课次没有绑定任何 slot，不能依据教师、课程名或上课时间自动猜测。2026-10-29 用户确认：Edit Schedule 应列出这些课次，由管理员选择一个当前 slot 作为继承者；此后该 slot 的现任老师继承这部分时间线，后续换老师继续随其流转。系统须持久化选择，并使 1-on-1 列表、课次详情和适用操作权限使用同一归属；不得改写实际授课老师或历史扣课。对多 slot、拆分及共享课包，必须避免同一条记录被重复继承或跨课包误分配。

## 3. 调整固定排课：旧 slot 与新 slot 的历史继承

本画面先列出原有 slot，再配置新周期的 slot。原有 slot 列表要显示**之前负责的老师名单**，同时显示每个来源 slot 的周几、时段、课程名称、历史课次数及已扣课时，供管理员识别历史属于哪段排课。同一老师负责多个旧 slot 时，必须分成不同来源项；只凭老师姓名无法确定具体课程历史。旧 slot 曾多次换老师时，来源项列出该 slot 历任老师，但以该 slot 的完整时间线作为一个历史来源。

每个新 slot 都有“继承此前记录”选择。管理员可以从上述旧来源中指定：**哪一个新 slot 的现任老师，接手显示哪一个旧 slot 的完整历史时间线**。选择结果在预览中用“旧时段与老师 → 新时段与老师”展示，保存后持久有效；日后该新 slot 再换老师，时间线继续随其继承关系流转。系统不能仅根据老师姓名或相近上课时间自动猜测继承者。

### 一个旧 slot 拆成两个新 slot

例如，原来 `周一 13:00–15:00 · A 老师`，调整后变成 `周一 13:00–14:00 · B 老师` 和 `周一 14:00–15:00 · C 老师`：

1. 管理员为 B 或 C 的新 slot 选择“继承 A 原周一 13:00–15:00 的记录”。该旧 slot 的历史时间线必须有**一个明确继承者**。
2. 同一份旧历史只能指向一个新 slot，不能同时添加到 B 和 C 的 Lesson records 中，也不能生成第二份消课记录。另一个新 slot 从新周期开始自己的时间线。
3. 历史日期、课次 ID、实际授课老师 A、确认状态及原扣课流水均保持原样。继承只决定新老师在哪里查看这段历史；不会把 A 实际教授的课记为 B 或 C 授课，也不重新扣课。
4. 两个新 slot 的未来分配额度分别输入、分别生成课次；继承历史不自动复制旧 slot 的分配额。新周期的可分配总额以课包真实剩余和其他占用为界。

有历史课次的旧 slot 在调整后仍有新固定排课时，保存前必须为其指定且只指定一个继承者；没有历史的旧 slot 可以不指定。若新 slot 更换老师，继承者随新 slot 流转；不得因此在多个老师的当前课包入口重复计算同一历史课次。若 A 仍负责课包的其他 slot，A 的那些入口保留。

### 统计口径

修改固定时段或拆分 slot 建立**新周期**。继承来的已完成课次属于旧周期，显示在继承者的完整 Lesson records 中，但不算作新周期的 `Deducted`，也不增加新 slot 的 `Allocated`。课包 `Total / Starting / Remaining` 仍由原账本决定。只有新周期的实际分配及以后确认的消课改变新 slot 的周期统计。

例如旧 slot 已消 4h、可继续安排 6h，拆成 B 的 4h 与 C 的 2h；若 B 继承旧历史，B 可看到 A 的 4h 历史，但新周期 B 为 `4h 已分配 / 0h 已扣 / 4h 剩余`，C 为 `2 / 0 / 2h`。此前已扣的 4h 不会再次扣课包。

### 旧课次与待处理记录

- 已最终处理的历史课次、正式请假及其记录保持原事实，按选定继承关系展示。
- 调整画面列出受影响的旧课次：哪些已保留、哪些未来普通课将被替换、哪些单次调整或补课需要保留。
- 对已经开始但未最终处理的旧课次，保存前给出具体清单。管理员可以先去处理；若选择继续重排，则按既定规则撤销这些未处理记录并回收其额度。不得因选择历史继承者而把已撤销的待处理课次重新带入新老师入口。
- 不允许因拆分或换老师修改已确认扣课、历史实际授课教师、课包 Starting，或为凑分配额暗中改写其他 slot。

## 4. 保存前反馈与验收

两个画面都应显示课包 Remaining、已占用及可追加课时，但各自只提交本画面负责的操作。调整固定排课的预览还需显示生效日期、旧→新 slot 对应关系、历史继承者、每个新 slot 的老师与额度，以及保留、撤销和新生成课次的数量及日期。资源冲突和余额不足要指出具体课程、日期、时间、老师和学生；保存失败时不留下部分变更。

验收至少覆盖以下场景：

1. 只给现有 slot 增减 0.5h，以及只换老师：周期不变，课时和 Lesson records 正确。
2. A 的一个 slot 拆为 B、C 两个新 slot：必须指定一个历史继承者；B/C 的历史展示、未来课次及新周期统计与预览一致。
3. 同一旧历史误选到两个新 slot、同一老师有多个旧 slot、旧 slot 曾多次换老师：界面能识别来源并阻止重复继承。
4. 拆分前有已确认、待管理员处理、未来普通课及单次调整课：各类记录按上述边界处理，已确认课时不重复扣减，待处理课次不静默丢失。
5. A 还负责其他 slot，以及 B 再交给 D：其他入口不受影响，已选择的历史时间线持续可查，旧实际授课老师不被改写。

本文只定义业务和交互边界；具体数据结构、接口及迁移方式在实现计划中确定。
