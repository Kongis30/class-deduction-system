# 重排时回收所有历史周期未处理课次：调整计划

更新时间：2026-10-30。业务要求见 [排课操作与历史继承需求](./edit-schedule-operation-split-requirements.md#重排前处理全部历史周期的未处理课次2026-10-30)。本文件是计划，并非已实现或已测试的结论。

## 目标与当前差异

在 Reschedule Lesson 保存前处理课包全部历史周期中已经结束、尚未最终确认的有效私教课次。管理员可以先逐条确认；也可以明确选择全部撤销回收，再按剩余额度重排。已确认历史与账本原样保留，新周期不得重复占用这些课时。

目前前端从 1-on-1 Lessons 数据中收集待处理课，但按 `currentRule.id` 过滤；后端重排时也先按当前规则取得课次，回收函数只处理该批课次。更早已结束规则的课次另用于保存时的余额预留，但不会进入回收清单，因此“回收”无法覆盖全部历史周期。服务端仍须独立校验，不能仅放宽前端筛选。

## 实施顺序

### 1. 统一范围和金额口径

- 追踪规则版本、无规则课次、共享课成员和现有有效状态，定义一处服务端查询：返回该课包**可证明归属**的、所有周期内已结束且未最终确认的私教课次；去重并保留每条原规则、组成员及当前状态供后续验证。
- 区分已确认、待老师、退回、待管理员、已取消／已回收、正在进行、未来普通课、未来已调整课和补课。确认和过往回收记录不重新处理；正在进行的课次作为阻止重排的单独情况；未来课继续使用对应保留或替换规则。
- 从实际持久化的课次、记录和课包账本计算：回收的未确认计划时长不改变课包余额；新 slot 总分配加仍需保留的例外及其他有效占用，不得超过可用余额。共享课逐个校验成员，避免重复计算或只对主学生生效。
- 定义清单与保存时的轻量一致性校验：传递用户看到并同意回收的课次身份及必要状态信息，后端重新查询和锁定后比较。若出现新增、删除、确认、调课或共享成员变化则拒绝并要求刷新；不通过宽泛布尔值回收用户未见过的记录。

### 2. 后端先实现完整回收与事务保障

- 将现有只处理当前规则的检查和回收调整为上述统一范围，支持跨规则与有确切归属的无规则课次；保留当前规则选择、历史继承和即时重排的既有语义。
- 对已结束的待处理课全部确认后正常继续；管理员选择回收时，事务内按稳定顺序锁定相关课包／共享成员、课次与记录，核验后整体软删除未确认提交和课次，并逐课写审计。共享课有任一已确认记录或成员状态无法安全统一时，拒绝并提示，不能局部回收。
- 回收后重新读取占用并执行现有额度、单 slot 覆盖和冲突校验；再结束旧规则、处理未来普通课并生成新周期。任一校验失败、并发冲突或写入异常时整体回滚，课包余额、已确认记录和用户未修改的老师分配保持不变。
- 同时核查确认旧课、实际课时大于计划、单课 Adjust、正式请假／补课、退回与撤销确认等入口：在仍存在保留例外或历史遗留课时，最终扣减后的余额必须覆盖其他有效分配和课次。不能仅依赖重排时的预留或依靠修改老师分配来掩盖超额。

### 3. 前端接入真实清单

- Reschedule Lesson 打开时使用服务端返回的跨周期清单，而非从某个老师视图或当前规则推断；显示日期、时间、课程、老师、处理状态和合计课时，附带“去 1-on-1 处理”及明确的全部回收选项。
- 用户先处理后返回时重新获取最新清单、余额和保存所需状态；选择回收时提交与清单对应的决定。数据变更、部分无法回收或余额／冲突不足时，指出实际问题和下一步，不暴露内部 ID。
- 进行中的课次显示阻止原因；未来例外显示它们将保留或交接及占用，不与已结束课混为同一个回收选择。桌面和移动端均能看到清单与保存反馈。

### 4. 回归与验收

对每个场景分别核对课包 `Total / Starting / Remaining`、各老师本周期 `Allocated / Deducted / Remaining`、实际排课、确认记录、历史时间线、占用与账本。测试包括：

1. 跨三个周期的待老师、退回和待管理员课次混合；选择全部回收后都不能再次确认、显示或占用；先逐条确认则扣课一次，随后重排按新余额计算。
2. 已确认历史与未确认课次同在，旧课包含无规则但归属明确的记录；检查历史、实际老师、流水不变且没有跨课包误删。
3. 部分用户已在另一个窗口确认、调整或新增课次；保存拒绝并刷新，所有原记录和新排课均无部分写入；重复提交不会重复回收。
4. 进行中的课阻止重排；普通未来课被替换；未来单次调整及补课按可证实的保留／交接规则处理。保存失败后所有数据恢复原样。
5. 共享课多学生、多规则、多老师；所有成员一致回收，已确认／成员变化及锁竞争安全失败，不重复计算或改变另一课包的扣课事实。
6. 旧课保留例外的实际扣减大于计划预留、管理员改判、当前周期加减 0.5h、换老师、单课调整、请假补课和余额减少；检查任何入口都不会让有效安排或剩余分配超过实际可用余额，错误说明具体差额及处理方式。
7. 真实快照隔离库中重放旧规则遗留及新规则操作，比较数据库课次与账本；浏览器测试选择先处理、全部回收、刷新变化、出错回滚及移动端显示。模拟测试不能替代真实数据库和页面测试。

### 5. 完成与发布

整理已替代的旧范围判断，保持一套清晰的查询与事务逻辑；记录测试结果、尚未覆盖的业务边界和历史数据影响。通过核心场景后按用户要求提交并同步部署前后端。历史线上数据先只读审计和备份，不能因为新规则上线就批量回收或修改原始数据。
