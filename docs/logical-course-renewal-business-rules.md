# 同一课程续课：业务规则与页面一致性方案

> 状态：目标业务规范，2026-10-24 补充订单归属规则。本文用于实现和验收；“目标”不表示线上已经具备该行为。

本规范定义**真实续费**。原报名录错才更正原有课程行；后续续课或加报属于新的课程购买行，但仍追加到当前 enrollment order。订单是收据和付款的归属单位，不因续课或加报拆分订单。不同课程行保留各自价格和权益；是否属于同一逻辑课程由 Product、Teaching project 和兼容计量单位决定。

## 1. 用户要完成的事

学生继续上**原来那门课**时，管理员应在原课程入口操作续课。保存后，Schedule、Data Summary 和相应消课页面继续显示这一门课的**一条课程记录**，数量或有效期随购买增加；老师分配、已上课次和历史付款不被重置。不同 Registration plan 只决定本次续购的范围和价格，不自动产生第二门供运营管理的课程。

这里有三种不同的“记录”，必须分清：

| 对象 | 含义 | 续课后的处理 |
| --- | --- | --- |
| 逻辑课程／课包 | 学生正在持续学习的这门课；各业务页面的主记录 | 保持同一身份，展示累计权益和当前状态。 |
| 购买记录（订单行、付款分摊） | 某次购买了多少、按哪个方案和价格付费 | 每次购买保留独立订单行和费率；续课与加报行仍属于同一订单、收据及付款账本。 |
| 权益段 | 这次购买对应的课时、课次或日期范围 | 保留来源、起止和消耗关联；团课可有多段，私教仍使用原课包。 |

**“Schedule 更新原记录”指课程列表中的一条主记录及其累计余额更新，不等于覆盖原订单行或历史课次。**不同费率的购买仍分行计价和分摊；这些行共享订单身份，便于同一张收据和付款账本继续管理。

## 2. 怎样判定“续原课”

1. 操作必须从指定的原课程发起，携带原课包／权益 ID。不能只凭学生姓名或相同产品自动合并两笔独立报名。
2. 学生必须相同；Product 和 Teaching project 必须相同。Registration plan **可以不同**，因此可以按新的两个月费率续接原来的四个月课程。实际班级或老师可按正常调班、排课规则改变，不改变逻辑课程身份。
3. 计量单位必须兼容：小时接小时、课次接课次、月份接月份。月数不能未经明确换算和人工确认就变成“剩余课时”。不兼容时明确阻止续接，允许作为新课程单独报名。
4. 从最新有效权益续接。新权益不能与旧权益重叠；按月班课应从原期限后的**下一次有效上课日**开始。存在后续续购时，不能从更早课程行再次续接或缩短后续权益。
5. Product 或 Teaching project 不同，或操作员明确选择“新课程”，则生成独立逻辑课程。名称相同但未指定原课程来源，也不能暗中合并。

## 3. 三种计量方式的统一结果

### 3.1 1-on-1：按小时的原课包

- 续购 `H` 小时后，原 `course_package.id` 不变；`totalHours` 增加 `H`，`remainingHours` 增加 `H`，历史 `consumedHours`、`openingUsedHours`、已确认课次和原价格不变。若有赠课，按赠课规则单独列明。
- Schedule 的学生课包列表仍是一条，显示新的 Total／Remaining；1-on-1 消课页用同一课包 ID 显示同样的数字和完整课次时间线。续费本身**不产生已上课次，也不复制旧课次**。
- 老师的 `allocated`、`remaining with teacher` 只由 Edit Schedule 的分配和实际消课决定。续费增加的是课包可分配余额，**不得擅自给任一老师增加 allocated**。若要让未来课次使用新增小时，管理员在原排课上分配；不改变历史排课周期和老师归属。
- 消课或 Undo 继续按原课包记账；`remaining = total - opening used - 有效净扣课`。退款、撤销本次续购时只冲回本次尚未消耗且未被有效排课占用的权益，不能把整门课及其他购买一并取消。

### 3.2 班课：按课次

- 页面上一条学生逻辑课程；购买课次累计，已使用课次沿用班课现有的**同一学生、同一上课日只消耗一次 session**口径，只计最终有效确认，`remainingSessions = 累计购买课次 - 净已用课次`。同一 occurrence 的重复确认也不能重复扣减。
- 每次购买仍有自己的权益段和订单行。确认具体课次时按上课日期及班级匹配唯一有效权益段，`lesson_record.class_enrollment_id` 继续指向该段，避免把旧课次扣到新购买上。Undo 回到该段并刷新逻辑课程的汇总余额。
- Schedule 列表显示一条累计余额；展开可查看每次购买的课次、费率及有效日期。若实际班级已改变，各班的点名名单仅显示该班对应时段，不在同一班级里重复列出该学生。

### 3.3 班课：按月份／有效期

- 续购增加的是**上课资格的有效期间**，不是小时。Schedule 中同一学生课程显示一条记录及累计有效期；“剩余”显示剩余天数／到期日，必要时显示购买月数，不伪造 `remainingHours`。
- Data Summary 的 Period 从第一段开始到最新有效段结束；只有相邻衔接的有效段才显示为连续区间。若允许有空档，必须明确展示分段，不能把空档误写成已购买期间。
- 班级课表 `lesson_occurrence` 属于实际班级，不因一个学生续费而重新生成或复制。确认上课时依据上课日找到该学生的唯一有效权益段；每个学生在同一次课上最多产生一条有效消课记录。

## 4. Edit Receipt／Add course 的交互与计费

1. 从原课程点续课后，完整显示原 Product、Teaching project、Registration plan、实际班级、购买数量、起止日期、Attendance、原价与已用量，供用户对照；原行不参与**本次**重复收费。
2. 新购买行预填原 Product／project，允许改 Registration plan、数量、Attendance、实际班级和首课日期。保存前展示“原课程累计值 → 续课后累计值”、本次应收／已收／欠款及排课影响。
3. 相同 Product／project 且规则兼容时，新购买计入原逻辑课程；不同则按新课程创建。新费率只作用于新购买，原四个月仍按原四个月的成交价保留；例如原购四个月 $1,600、再购两个月 $600，课程累计六个月，财务上保留 $1,600 和 $600 两笔。
4. **真实续费应形成新的课程行和本次价格事实，保存在当前订单与收据中**。原行的历史金额不因续费被覆盖；同费率可以直接增加原行数量，费率不同则 Add course 新增一行并选择 Registration plan。新增付款作为当前订单的新付款流水。只有纠正“原报名时填错了数量”才属于原行更正；这两种操作必须在界面上区分。
5. 原购买行的更正、续课行的退款／撤销应只影响对应课程行及权益段，再重新计算逻辑课程累计值。禁止按课包 ID 直接删除整门课，或把已使用的权益扣回成负数。

## 5. 各页面的数据口径

| 页面 | 必须显示和更新的内容 | 不应发生的事 |
| --- | --- | --- |
| Schedule／Edit Schedule（1-on-1） | 同一课包 ID 的 Total、Remaining 更新；老师分配单独保持原值，新增可分配余额可见。 | 自动改老师 allocated、重置排课周期、复制未来课次。 |
| 班课 Schedule／学生名单 | 按学生＋逻辑课程汇总为一条，显示累计课次余额或最新有效期；展开可看购买段。 | 同班同学生因续费出现两条并列课程记录。 |
| Data Summary | 同一逻辑课程一行，Period／余额为累计口径；各购买金额按原订单与月份筛选口径分别计入。 | 把两笔收费吞成一笔、把已撤销段计入有效期。 |
| 1-on-1 消课 | 对 1-on-1 续课，原课包的 Total／Remaining 和课次列表即时更新。 | 将班课的月份续费写入私教课包，或新建第二个私教消课入口。 |
| 团课消课／点名 | 确认课次按日期定位权益段，汇总结果回写同一逻辑课程。 | 同一次课双重扣减或把新时期课次算到旧购买。 |
| 收据／订单 | 同一订单收据中清楚展示各课程行的方案、费率、金额；付款流水及课程分摊属于该订单。 | 为续课或加报另建订单／收据，或用新方案改写旧购买价格。 |

页面刷新后必须从服务端取得同一汇总口径；不能只在当前浏览器把两行临时拼成一行，导致其他入口、打印和权限视图不一致。

## 6. 保存和冲正的完整性

- 服务端在一个事务内校验当前订单、续课来源、学生、产品／项目、单位、相邻期限、价格及冲突，并向原订单新增课程行、权益和必要付款分摊；失败全部回滚。并发续同一课程时锁定来源，防止两个续购都认为自己是“最新一段”。
- 有效期和余额按**有效权益与有效扣课**重算，不能把可修改的订单快照直接当作余额，也不能让后台同步任务用旧流水的 `balance_after` 覆盖续费后的余额。
- 退款／撤销只按购买行和该段已使用、已占用的数量计算可退权益；若无法唯一归属或会影响已确认课次，明确阻止并列出受影响记录，不猜测、不自动修改老师 allocated。
- 保留操作者、时间、来源购买、目标逻辑课程、变更前后值及价格快照。旧课次、原收据和付款不因续课被覆盖。

## 7. 当前实现与必须补齐的差距

- **已经具备：**1-on-1 续购在原 `course_package` 上累加 total／remaining；班课新权益可关联原 `logical_course_id`；Data Summary 前端能把相同逻辑课程合并并扩展 Period。
- **尚未达到：**班课 Schedule 的 `listEnrolledStudents` 逐条返回 `class_enrollment`，同一学生续课会显示两行；按月班课没有“小时 remaining”，也没有统一的课程级有效期展示。上一轮隔离测试已复现这点。
- **需要梳理：**原收据行直接加月份的现有流程属于修改原购买；要作为真正续费入口时，需改为增量购买事实。退款／取消对同一 1-on-1 课包多笔购买的分摊能力也需在开放自动处理前补全。

实现以现有 `course_package` 和 `class_enrollment.logical_course_id` 为基础，优先在服务层增加一个**课程级汇总口径**供 Schedule、Data Summary 和消课页复用；历史购买和权益段仍保留。不为展示合并另建一套可被人工维护的平行余额表。

## 8. 验收场景

1. 原四个月＋不同费率两个月：同一订单和收据下保留两个价格不同的课程行；Data Summary 一门课、Period 延到第六个月；班课 Schedule 同一学生一条主记录、有效期更新；旧时期消课仍关联旧权益。
2. 同一 1-on-1 课包再买 10h：Schedule 和 1-on-1 消课均在原课包上增加 10h Total／Remaining；老师 allocated 不变；消课、Undo 和余额同步后数值仍一致。
3. 课次包再买 8 节：Schedule 累计购买／已用／剩余准确；同一次课只扣一次；Undo 后恢复一次。
4. 新方案改价、Attendance 或实际班级：新购买按新价，历史价不变；已确认旧课次不迁移；新班名单只在生效日期后出现。
5. 重复提交、旧段续课、期限重叠、单位不兼容、退款已用权益：分别明确阻止或幂等处理，无第二条重复主记录，也无部分写入。
6. 月份筛选、打印、重新登录、不同角色查看时，课程身份和余额仍一致；财务汇总只计算筛选范围内的购买款项，Period 按该逻辑课程完整有效期展示。
