# Edit Schedule 弹窗前端设计与实现计划

> 状态：实施中。对应 [排课操作拆分与历史继承需求](./edit-schedule-operation-split-requirements.md)，仅设计 1-on-1 课包的编辑入口；Create Schedule 和现有单节／单周 Adjust 保持各自流程。

## 1. 交互框架

页面上的按钮仍叫 **Edit Schedule**。点击后打开一个弹窗，标题下固定显示学生、课包、当前固定排课及课包课时摘要。弹窗顶部用两个清楚可见的选项切换内容：

1. **调整当前排课**（默认）：已有时段保持不变，只改指定时段的老师、分配课时、课程名称、教室。
2. **调整固定排课**：修改每周上课时段或生效日期，增删、拆分时段，并指定旧历史的继承者。

两项在同一弹窗内分别有自己的字段、校验、预览和保存按钮。切换视图时，如果当前视图有未保存修改，先提示放弃或留在原视图；不能把其中一个视图的草稿偷偷带到另一个视图。弹窗中的单节／单周调整只提供现有 Adjust 入口说明，不作为第三套固定排课表单。

公共摘要只展示与决策相关的数字：课包 Remaining、已经占用的课时、目前可追加的课时。数值由服务端按现有课包和预留规则计算；老师的 `Allocated / Deducted / Remaining` 则显示在对应时段卡片中，避免把课包余额误当成某位老师的可排课时。

## 2. 视图一：调整当前排课

首屏展示已有时段卡片，而不是整张周历。每张卡片固定显示“周几 · 时间 · 课程名称”和现任老师，下面显示该时段已分配、已扣、剩余课时；只编辑需要修改的卡片。

| 字段或动作 | 前端表现 |
| --- | --- |
| 老师 | 下拉框按名称排序。选成新老师时，展示时间线和未处理操作权自动交接的说明。 |
| 分配课时 | 显示当前总额与增减输入，支持 0.5h 步进；同时显示预计调整后总额。保存后只增补或回收该时段安全的未来普通课。 |
| 课程名称、教室 | 在卡片内编辑；提示只同步适用的未来课程。 |
| 周几、时段、单节时长、原起始日期 | 只读；旁边提供“需要改时间？切换到调整固定排课”。 |
| 历史消课展示 | 换老师时自动把该 slot 的完整时间线交给新老师；提示原授课老师、消课流水和工资记录不变。 |

底部预览按卡片列出变化：哪位老师接手、当前周期账目是否变化、未来课次增加或回收多少，以及完整历史自动交接给谁。仅换老师时说明新老师接手待处理操作权；原老师若仍负责其他时段，那些时段不受影响。保存成功后刷新排课摘要和 1-on-1 Lessons 使用的数据。

## 3. 视图二：调整固定排课

按“新排课 → 历史对应 → 预览”组织内容；可以在一个弹窗内向下完成，不再套第二个弹窗。

### 新排课

顶部填写**生效日期**，显示原排课起始日期作参考。复用现有周历控件选择新的每周时段；选中后在周历下生成新时段卡片，分别填写老师、教室、课程名称和新周期分配课时。已有安排先复制到草稿供用户修改，保存前不动正式数据。删掉或拆分时段后，新卡片用“周几 · 时间 · 老师”区分。

### 历史对应

周历旁或其下方显示“之前的时段与老师”清单：每项包含原时段、课程名称、历任老师、已完成记录数／课时和待处理数。同一老师的不同旧时段分别显示，避免选择来源时只看到姓名。

每个新时段卡片上提供“继承此前记录”选择，选项标签为“原时段 · 原老师（历史 N 节）”。选择后显示清楚的箭头关系，例如 `原周一 13:00–15:00 · A → 新周一 13:00–14:00 · B`。系统按旧时段标识保存关联，不按老师姓名或相似时间猜测。旧时段曾先后由多位老师负责时，整条时间线作为一个来源，选项中列出这些老师。

一个旧时段拆为两个新时段时，由用户选其中一个作继承者；另一新时段从新周期开始自己的时间线。界面实时把已选来源从其他新时段的可选项中移除，并在来源清单标明“已分配给……”；仍有未指定继承者的旧历史时，预览中明确指出。一个新时段如需接收多个旧时段，选择控件可展示多个来源，但每个旧来源在整个新排课中最多出现一次。此项只处理时间线关联，绝不复制课次或旧分配额。

### 预览与确认

预览显示生效日期、每个新时段的老师及额度、旧→新历史对应、旧课次的保留与撤销、未来新生成课次及余额变化。继承历史在新老师 Lesson records 中可见，但预览须区分“旧周期已扣”与“新周期已扣”，避免用户以为新老师授课或新周期重复扣课。

旧课次若已开始且未最终处理，进入本视图时只显示提醒；在预览阶段列出具体课程、日期、时间和老师。管理员可返回先处理，或明确选择继续并撤销这些未处理记录、回收额度。错误提示定位到具体新时段或继承关系；点击提示能滚动并聚焦对应字段。

## 4. 两个视图共同遵守的操作细节

- 底部按钮固定可见：`Cancel`、`Preview changes`；预览通过后显示 `Confirm & save`。保存按钮不因缺少普通必填字段永久变灰；点击时标红字段并滚动到第一个问题。提交中和初始化数据尚未加载完成时才阻止重复提交。
- 页面加载时保留服务端规则快照；预览和确认使用同一次草稿版本。若其他管理员期间修改排课、确认消课或更改课包，提示刷新后重新预览，不能保存旧预览的不同结果。
- 冲突提示使用“冲突类型：课程、日期、时间、老师、学生”，不显示原始 ID。课时不足指出可用额、申请额和差额。
- 桌面端弹窗有固定标题、操作切换和底部按钮，内容区独立滚动；移动端单列排列，先显示当前时段／新时段卡片，周历可展开，不依赖横向拖动找到保存或历史来源。
- 切换视图、关闭弹窗或保存失败都不应无声丢失输入；保存成功后才清空草稿。

## 5. 实现顺序

1. **确定接口数据。**在现有排课详情中明确当前课包余额、每个旧时段的历史数量及历任老师、稳定的旧时段标识。固定排课预览和保存使用显式的“旧时段 → 新时段”继承关系；当前 slot 换老师时自动交接其时间线。服务端需要校验来源唯一性并持久化。预览与保存必须使用同一计算口径。
2. **拆开 Create 与 Edit 的前端状态。**`RecurringScheduleView.vue` 只负责选择课包、打开弹窗和保存后刷新；现有 Create Schedule 表单先保持原流程。把 Edit 部分移入独立弹窗组件，保留共享的课包摘要和资源选择工具，不再以同一个可变 `editForm` 同时承载创建、额度调整和重排。
3. **实现“调整当前排课”。**先做只读时段卡片、局部字段、0.5h 增减与老师交接选项；建立只允许已有时段和同周期字段的请求。核对不改时段、只改老师、只增减课时、两者一起改及改课程资料的预览与保存结果。
4. **实现“调整固定排课”。**复用 `WeeklyTimeSelector`，增加生效日期、新时段卡片、旧时段与老师清单及历史继承选择；先支持一旧一新和一旧拆二，再覆盖多旧合一、连续两次换老师。服务端显式映射生效前，不开放该视图的最终保存。
5. **接通差异预览及错误定位。**把目前打开弹窗前统一触发的待处理课次提示改到对应视图的预览阶段；当前视图按交接规则提示，固定排课视图列明撤销和回收。完成响应式布局与键盘操作。
6. **按业务路径验收。**检查排课日历、1-on-1 Lessons 的历史与操作权、老师 `Allocated / Deducted / Remaining`、课包账本、待处理回收、资源冲突、拆分后的唯一继承和保存失败回滚。删除已被新视图取代的旧表单分支和重复提示，避免并存两套判断。

本计划是前端交互及实施顺序；后端显式继承关系和预览能力是第 4、5 步启用保存的前置条件。
